# 使い方のスクショ

使い方のページ（`lib/screens/help_screen.dart`）に出す画像。画面を変えたら、変わった画面だけ撮り直す。

- `wide/`：PC の幅。1280×720、倍率1
- `narrow/`：スマホの幅。390×844、倍率2（縦は要る所まで切り取ってよい）
- 名前は節ごとに決まっている：`new_note`・`input`・`review`・`check`・`history`・`rewind`・`edit`・`materials`・`search`・`share`・`notices`

## 例の中身

どの画像も、審査用の見本（`docs/mock-data/restaurant.md`、`api/src/seed.ts` の `seedPreset`）と同じ例でそろえる。登場人物・店はすべて架空。

- ログインは新人の ID `newbie`（名前「あおい」）。共有の相手は `tencho`（名前「店長」）。どちらも撮るための API にだけ作り、メンバーの ID は使わない
- ノートは「キッチンマニュアル（定食屋 みのり）」（資料「店舗マニュアル」つき）・「ホール接客マニュアル（定食屋 みのり）」・「閉店作業メモ」（店長に共有）
- 画像ごとの画面
  - `new_note`：題名「仕込みメモ」と本文3行を入れたところ
  - `input`：「田中さんから、味噌汁の塩は小さじ1/2でいいと言われた」を入れたところ（未整理メモは無し）
  - `review`：「田中さんに、忙しい日は大盛りは200gまでと言われた」を送り、結果の「確かめる」を押したところ（未整理メモは無し）
  - `check`：キッチンマニュアルの確認リストで、田中さんの「ガスの元栓」を開いたところ
  - `history`・`edit`：キッチンマニュアルの履歴と、「炊けたら10分蒸らす」の行を押したところ
  - `materials`：キッチンマニュアルの資料「店舗マニュアル」を開いたところ
  - `search`：「レジ」で探したところ
  - `share`：閉店作業メモの「共有」を開いたところ
  - `notices`：自分の名前を押したところ（新しい通知が2件）
  - `rewind`：リワインドを ON にしたところ（見本の未整理メモ3件）

## 撮り方

1. 上の例だけを入れたメモリ上の API を、普段の API（8787）とは別のポートで立てる。`api/scripts/seed-preset.ts` と同じように `seedPreset` で `MemoryStore` に入れ（資料のトークン数は `fakeCountTokens`）、AI は偽物（`fake-ai.ts`）にする。`input`・`review` は、入れたあとに未整理メモを消す（`removeMemo`）。偽物は発言者を「〇〇さん・先輩・店長」などでしか読まず、項目の頭の言葉が同じだと食い違いにするので、例文は上のものを使う
2. アプリをその API に向けてビルドして配る：`fvm flutter build web --dart-define=API_URL=http://127.0.0.1:<そのポート>`
3. Chrome を外から操作して撮る（Playwright など）。読み上げ用の木を出す（`flt-semantics-placeholder` を押す）と、ボタンを名前で探して押せる。PC の幅は 1280×720・倍率1、スマホの幅は 390×844・倍率2。リワインドは `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream` で偽のマイクを使う
4. API はメモリ上なので、照らし合わせをすると記録が残る。1枚撮るごとに API を立て直し、上の例だけの状態から撮る（前の画像の記録が写り込まないように）
5. スマホの幅で下が空く画像（`new_note`・`search`・`notices`）は、要る所まで切り取る
