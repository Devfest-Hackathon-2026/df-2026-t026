# Flutter UI ルール

目的は「どのアプリにも見える既定値」ではなく、使い慣れた文書アプリの型（Mobbin で調べた Notion・Confluence・GitBook など）に沿いつつ、このアプリにしか無いもの（衝突の提示と確認印）をはっきり見せること。部品は moon_design（ADR 0004）、アイコンは lucide。`app/test/ui_rules_test.dart` が下の一部（禁止部品・アイコン・リテラル・影・グラデーション・絵文字）を機械で検査する。

## 見た目の考え方

- 画面では、扱うものを「マニュアル」でなく「ノート」と呼ぶ（spec）。職場のマニュアルはノートの一つ
- 楽しさは Web の流行り（グラデーション・すりガラス・パステルの色回し・絵文字・何でもピル型）からではなく、ホワイトボード（Miro）の付箋と、ハンコから取る。使うものは「ノートに、言われたことを貼っていく」というこのアプリの形を表すものだけにする
- 画面の地は方眼のある明るい灰色（`shell`・`grid`、`GridBackground`）。クリームやベージュの地は AI が作った画面の既定の色に見えるので使わない。ノート本文・入力欄・確認の画面は白い面（`PaperSheet`、影を付けないフレーム）に置き、記録と確認は右のパネル（狭い画面ではタブ）に置く。罫線で区切る一覧は、罫線が方眼とぶつからないよう白い面に載せる
- 色は、このアプリにある物の色と、差分・状態の色、操作の色だけにする。面は白（`canvas`）、文字は紺がかった黒（`ink`）、付箋は淡い黄（`sticky`）、確認印は朱（`stamp`）。差分と状態は、はっきりした緑（反映済み）・黄（あとで確認）・青緑（条件付き）・赤（消えた行）にする。くすませた中間色やパステルで「上品に」揃えない
- 主ボタンと選択中の印は青（`action`）にする。紫寄りの青や、紫から青のグラデーションにはしない。条件付きの青緑と紛れない青にする。朱は確認印だけに使い、印を目立たせる。色の付いた面を飾りとして増やさない
- 目立たせるのは衝突の提示（ノート ／ 言われたこと）と確認印（朱）。確認印は日付印の形で、このアプリの記録が証拠になることを表す
- 食い違いは急がせない。食い違いは「あとで聞くこと」で、記録した時点で解決を求めない。見つけたら確認リストに入れるだけにし、確定の入力欄は利用者が「確認できたので記録する」を押してから開く。黄は面を塗らず、線と小さなタグだけに使う
- 「口頭で言われたこと」は付箋（`StickyNote`）で見せる。付箋は淡い黄色1色にし、傾けず、下側にだけ影を付ける。誰が言ったかはアバターと名前で示す。付箋は言われたことだけに使い、案内や空状態には使わない
- 書体は1つ。題名・見出し・本文・UI・付箋の中まで印字（BIZ UDPGothic）で、題名は太さと大きさで分ける。丸ゴシック・手書き風・明朝風の書体は使わない（Miro の文字は丸くなく、付箋の中も普通の文字。手書き風の書体は AI が作った画面に見える）
- 書体は `app/fonts/` に同梱し、実行時に取りに行かない（google_fonts を使わない）。Web は OS のフォントを使えず、取りに行くと届くまで文字が出ない。書体を足すと最初の表示がその分遅れるので、足すときは `app/fonts/README.md` の手順で文字を絞る

## 情報配置

- スマホと PC の両方を本命として作る（spec）。デザインは1つで、画面の幅に応じて並べ方だけを変える。狭い画面は押して進んで戻る。広い画面では、画面を積んで戻るのを繰り返させず、並べて見せる
- 広い画面（`wideLayout` + `sidebarWidth` 以上）では、左にサイドバー（`WithSidebar`）を常に出し、「言われたことを記録」・ノート一覧・各ノート（あとで確認の件数つき）・「ノートを作る」へ直接移れるようにする。サイドバーから移るときは入力ページまで戻してから開き、画面を積み重ねない
- 題名は上部バーではなく、内容の頭に大きく置く（`text.display`）。上部バーは戻る・パンくず・その画面全体の操作だけ
- 題名の下のメタ情報（記録の数・差分の数・あとで確認の数）は、それぞれ別の要素として並べる。`・` や ` · ` でつながない
- アプリを開くと最初に入力ページが出る。どのノートかを先に選ばず、常時待ち受け（直前60秒をメモリ保持し、言われた後に1タップで切り出して送信）・テキスト（音声入力つき）・ファイル（PDF／画像）で入力できる。常時待ち受け中は「端末内で直前60秒を保持中（送信していません）」の案内と音量インジケータを出し、いつでも一時停止できる。同じ画面に「あとで確認」への導線と最近の記録を置き、上部バーの「ノートを確認」からノート一覧へ進む
- 入力ページの書く欄は白い面に載せ、最近の記録は言われたことの付箋で並べる。広い画面では、書く欄とあとで確認を左、最近の付箋を右の2列にし、Ctrl/⌘+Enter でも送れるようにする
- 一覧は「題名と主ボタンを同じ行」にする。ノートは1冊を1枚の白い面（`PaperSheet`）として並べ、記録数は文字で、あとで確認の数だけを状態のタグで出す
- ノート画面には、言われたことを記録する入力欄を置かない（記録は入力ページ）。行を押すとその場に編集欄を開き、書き換え・下に行を足す・消すができる。末尾には「行を書き足す」を置く。直接書いた行は本人の文なので、左余白の色線・発言者の印・付箋に出さない。文書面にはノート本文、右パネルには「記録した発言」だけを置く。発言の項目は「誰が・いつ（アバター・名前・日付）→ 本文 → 状態」の順に並べる
- 食い違いは別の画面（確認リスト）にまとめる。「あとで確認」と「確認済み」の2つに分け、項目は「誰が・いつ → 食い違い（ノート ／ 言われたこと）→ 理由か確認の結果」の順に並べる。確認済みの項目には、誰がいつ確認したかを必ず付ける。ノート画面からは上部バーのボタンでいつでも開ける
- 確認リストは、広い画面では左に一覧、右に選んだ食い違いの詳細（比較 → 誰に確認するか → 確定の記録）を並べる。選んだ行は青（`action`）の枠で示す。狭い画面では一覧から詳細の画面へ進む
- 文書の変更行は、左余白の色線で示す。左余白の色線は変更の種類（反映済み・あとで確認）を表すときだけ使い、カードの枠の一辺を色付けする飾りには使わない
- ノートの食い違っている行には、行の横に「／ 誰（日付）：言われたこと」と「食い違い」のタグを出し、食い違っていることがその場で分かるようにする。行のどこを押しても確認リストを開く（その場で解決させない）
- 衝突は左右に並べ、どちらも同じ色（中立）で見せる。どちらが正しいかはアプリが決めない（spec）ので、赤／緑で塗り分けない。未解決であることだけを黄の印で示す。文言は「ノートの行 ／ 言われた行」の形を保つ
- 確認の結果を選ぶ所は、左右の比較と同じ並びの選択肢にする（左＝ノートのまま、右＝言われた通り、下＝別の内容）
- 狭い画面（`wideLayout` 未満）では、文書と記録した発言をタブで切り替える。タブの中にさらにタブを重ねない

## 部品

- 画面に見える部品は Moon（`Moon*`）か `lib/screens/common.dart` の自前部品だけを使う
- 使ってよい Material：`MaterialApp`・`Scaffold`・`Material`・`MaterialPageRoute`・`Theme`。Moon の入力欄が Material の祖先を要求するため、土台としてだけ使う
- 使わない Material：`Card`・`ListTile`・`AppBar`・`TabBar`/`Tab`・`Chip`/`ActionChip`・`ElevatedButton`/`FilledButton`/`OutlinedButton`/`TextButton`/`IconButton`/`FloatingActionButton`・`TextField`・`Radio`/`RadioListTile`/`RadioGroup`・`AlertDialog`/`showDialog`・`SnackBar`/`ScaffoldMessenger`・`CircularProgressIndicator`/`LinearProgressIndicator`・`CircleAvatar`・`Divider`/`VerticalDivider`
  - 代わり：ボタン→`MoonFilledButton`/`MoonOutlinedButton`/`MoonTextButton`/`MoonButton.icon`、入力→`MoonTextInput`/`MoonTextArea`、ダイアログ→`showMoonModal`、通知→`MoonToast`、読み込み中→`MoonCircularLoader`、タブ→`MoonTabBar`、切り替え→`MoonSegmentedControl`、アバター→`MoonAvatar`、ラベル→`StatusTag`（common.dart）
- 例外：日付選択だけは Moon に無いので `showDatePicker` を使う。色はテーマの `ColorScheme`（トークンから作る）に従わせる
- アイコンは `LucideIcons` だけ。`Icons.*` と、moon_design が再エクスポートする `MoonIcons` は使わない
- アイコンは、言葉だけでは意味が取りにくい所（戻る・コピー・日付・閉じる）と状態の印にだけ付ける。見出しや行ごとの飾りアイコンは付けない
- 発言者のアバター（名前の頭文字）は「誰が言ったか」を表す情報なので付けてよい。地はどの人も同じ灰色（`avatar`）にし、色で人を区別しない

## トークン

- 色・余白・角丸・文字スタイルは `context.tokens`（`lib/theme.dart` の `AppTokens`）から取る。`Color(0x…)`・`Colors.*`・数値を直接書いた `EdgeInsets`/`SizedBox`/`BorderRadius`/`fontSize` は `theme.dart` 以外に書かない
- Moon の色・角丸・書体・影も `theme.dart` でトークンから作る。Moon の既定（紫の主色 #5C33CF、純黒）を画面に出さない
- 色は役割の名前で持つ（`shell`・`canvas`・`ink`・`inkMuted`・`rule`・`added`・`removed`・`pending`・`qualified`・`stamp` など）。文字は紺がかった黒（`ink`）で、純黒 `#000000` は使わない。補足の文字は `inkMuted`
- 余白は `space.xs`(4)〜`space.xxl`(40) の段階だけ。まとまりの内側は狭く、まとまりの間は広くして、全部を同じ値にしない
- 角丸は役割で分ける：操作するもの（`radius.control`）、面（`radius.surface`）、紙と付箋（`radius.paper`、ほとんど丸めない）、アバターと状態のタグ（`radius.round`）。何にでも同じ角丸を付けない

## 構成

- グラデーション・すりガラス・光彩は使わない。影は付箋（`StickyNote`）の下側にだけ付ける。白い面・カード・タグ・衝突の左右の面には付けない。本文の区切りは罫線（`rule`）と左余白の色線で付ける
- 箱の中に箱を作らない
- 文字は左揃え。中央揃えは、空状態のように画面に一つしかない短い案内だけ
- 番号（1・2・3）は、本当に順に進む手順にだけ付ける
- 主ボタン（filled）は、一つのまとまりにつき一つ。他は outlined か text にする
- 動きは利用者の操作に応えるもの（開く・閉じる・確定）だけ。弾む動き、表示時の入場アニメーションを付けない

## 状態

- データを読む画面は、読み込み中・空・エラーを必ず出す。エラーには再読み込みの操作を付ける
- パネルの切り替えなど、利用者が選んだ表示はデータが変わっても勝手に切り替えない
- 送信中はそのボタン自体を読み込み中の表示にして、二重送信を防ぐ
- 空状態は次にすることへの誘いにする（何ができるかと、そのためのボタン）

## 文言

- ボタンは動詞か「何をするか」で書く（「差分を作る」「確定する」「承認して反映」）。「OK」「はい」「送信」は使わない。同じ操作は流れの中で同じ名前にする
- エラーは何が起きて、どうすればいいかを書く。謝らない
- 見出しを言い換えただけの説明文を付けない。絵文字は使わない。状態はタグの言葉と色で、画面はその題名で示す
