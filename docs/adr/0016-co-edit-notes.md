# 0016 共有したノートを全員で同じように編集し、同じ行の直しがぶつかったら選んでもらう

- 日付：2026-11-10
- 状態：採用（ADR 0013 の「共有された人ができること」を置き換える）

## 背景

- ADR 0013 の共有では、共有された人は「見る」と「行を直接直す」だけができ、言われたことの記録・書き込む前の確認・確定は持ち主だけができた。
- 利用者から、職場のマニュアルを全員で共有している Google ドキュメントのように、共有した全員が同じように編集したいという要望があった。そのうえで、だれが・いつ・何を変えたかは git のように追えるようにしたい。
- 全員が直すと、2人が同じ行を別々に直すことが起きる。今は、後から保存した人の行がもう無いので「行が見つかりません」で落ちるだけだった。

## 決定

1. **共有された人も、持ち主と同じことができる**
   - 言われたことの記録（ノートを選んで記録する・入力ページの振り分け）、書き込む前の確認（書き込む・書き込まない・言われたことを直す）、確定、共有の相手を見る・足す・外すを、共有された人にも許す。
   - ノートを消すことだけは、持ち主にしか許さない（Google ドキュメントで、編集者が共有を変えられても、消せるのはオーナーだけなのと同じ）。
   - 入力ページで記録先を選ばなかったときの振り分けと、書き起こしの語句のヒントにも、共有されたノートを含める。
   - 共有された人のサイドバー・入力ページ・「あとで確認」のページにも、共有されたノートの「あとで確認」を数える。
   - 共有の相手に、ノートの持ち主と自分は足せない。共有された人は自分を外せる（外すとそのノートを読めなくなる）。
2. **保存先は持ち主の下のまま（ADR 0013）**
   - 共有された人の書き込みも、`load` が返す `owner` の下に書く。土台（記録とパッチ）の形は変えない。
   - 認可の既定を逆にし、`load` は共有された人にも許す。持ち主に限るのは、ノートを消す（`mustOwn`）だけにする。
3. **同じ行の直しがぶつかったら、行ごとに選んでもらう**
   - 直接の編集（`POST /manuals/:id/edits`）で、書き換える・消す行がもう無く、その行を最後に書き換えた・消した反映済みのパッチがあれば、409 と `conflict` を返す。`conflict` は、元の行（`line`）、相手の直した行（`theirs`。消されていれば null）、相手が消した行の1つ上の行で今も残っているもの（`after`。無ければ null）、だれが（`by`）・いつ（`at`）直したか。
   - アプリは、元の行・相手の直し・自分の直しを並べたモーダルを出し、「自分のにする」「相手のままにする」から選んでもらう。「自分のにする」は、相手の行を自分の文に書き換える（自分が消そうとしていたなら相手の行を消す。相手が消していたなら `after` の下に自分の文を足す）新しい編集として送り、ふだんの編集と同じく衝突検知にかける。
   - 相手と同じ直しだった（同じ文に書き換えた・同じ行を消した）ときは、モーダルを出さずに今のノートを読み直すだけにする。
   - 行を足す編集で、足す位置の行が書き換えられていれば相手の直した行の下に、消されていれば `after` の下（無ければ末尾）に、だまって足す。位置が変わるだけで、どちらかの文を捨てることはないため。
   - 違う行の直しは、ぶつからずにそのまま両方入る（パッチを行の文字列で当てる。ADR 0001）。保存した人には、その時点のノート全体が返るので、ほかの人の直しもそこで見える。

## 理由

- 共有された人に許す呼び出しを一つずつ足すより、「消す以外はすべて」としたほうが、Google ドキュメントの編集者と同じで分かりやすく、書き忘れも起きない。
- 書き込み先を持ち主の下に保つので、データの持ち方（ADR 0013）・履歴（ADR 0008）・衝突検知はそのまま使える。
- ぶつかったときに後の保存を黙って通すと、先に直した人の文が知らないうちに消える。落とすだけだと、自分の直しが消える。git のマージの衝突のように、両方を並べて本人に選んでもらうのがいちばん取りこぼしがない。

## 採らなかった案

- 画面をいつも最新に保つ（配信や数秒ごとの読み直し）：Google ドキュメントに近くなるが、`load` は毎回すべてのコレクションを読むので、Firestore の読み取りが開いている間ずっと増える。保存のたびに最新が返り、ぶつかれば選んでもらえるので、「保存したときにそろう」git に近い形で足りる。
- 編集のたびに、読んだときの版を送ってもらい、版が古ければ必ず衝突にする：違う行の直しまで衝突になり、選ぶ手間が増える。
- 共有された人の直しを「提案」として持ち主が取り込む：利用者が選ばなかった（全員が同じように直す形を選んだ）。

## 割り切っていること

- 画面は自分で保存・読み込みしたときにしか新しくならない。ほかの人の直しは、保存したときか開き直したときに見える。
- 「自分のにする」を押すまでの間に、さらにほかの人が同じ行を直していれば、もう一度同じモーダルが出る。
- 持ち主の直接編集は、これまでどおり発言者「自分」で残す（ADR 0007）。共有された人が見ると、持ち主の編集した行には名前が出ない。衝突のモーダルでは、持ち主の名前で見せる。
- 言われたことを記録した人（だれが入力したか）は残さない。残すのは、だれが言ったか（`speaker`）だけ。
- 同じ文字列の行が複数あると、最初の行に当たる（ADR 0001）。
