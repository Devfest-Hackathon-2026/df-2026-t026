# 0014 未整理メモをサーバーに置き、端末をまたいで同じものを見る

- 日付：2026-11-10
- 状態：採用（ADR 0005 の「未整理メモは端末内（`shared_preferences`）に置く」を置き換える）

## 背景

- リワインドで切り出したメモは、ADR 0005 で端末内（ブラウザの `shared_preferences`）にだけ置いていた。
- 勤務中はスマホでリワインドを ON にしてメモをため、手が空いたら PC で整理して記録したい。端末内に置くと、ためた端末でしか整理できない。ブラウザのデータを消すと、整理する前のメモも消える。

## 決定

1. 未整理メモは `users/{userId}/memos/{id}`（`{id, at, text}`）に置く。`at` は切り出しボタンを押した時刻で、UTC の ISO 8601 で持つ。土台（`manuals` の下）や衝突検知とは別の場所にし、土台のデータ構造は変えない。
2. `POST /listen` は、書き起こしたら `at` とともにメモとして保存し、そのメモを返す。書き起こしと保存を1回の呼び出しにまとめ、待ちの段数を増やさない。書き起こせなければ保存しない。
3. `GET /memos`（切り出した順）・`PATCH /memos/:id`（書き直し）・`DELETE /memos/:id`（消す）を足す。消すのは、ほかの端末で先に消していても失敗にしない。
4. 入力欄に入れたメモ・1件ずつ記録するメモは、`POST /utterances` に `memoIds` で添える。記録できたら（関係するノートが見つかったら）サーバーが消す。記録先を選び直してもらうときは、送り直すまで残す。
5. アプリは、入力ページを開いたとき・読み直したとき（ログイン・記録・ほかのページから戻ったとき）と、アプリに戻ってきたとき（タブを開き直した・ほかのアプリから戻った）にメモを読み直す。
6. 前の版が端末内にためていたメモは、次にメモを読み直すときにサーバーへ移し（`POST /memos`）、端末からは消す。

## 理由

- メモはテキストと時刻だけで小さく、人ごとのデータ（ADR 0009）の下に置けば、ほかの人のメモと混ざらない。
- 記録したメモを消すのをアプリの別の呼び出しにすると、記録した後・読み直す前に消し終わらないことがあり、記録したメモが一瞬戻って見える。記録と同じ呼び出しで消せば、呼び出しも増えない。

## 採らなかった案

- 書き起こしの後にアプリが `POST /memos` で保存する：呼び出しが1回増え、書き起こしの結果が届く前にタブを閉じるとメモが残らない。
- Firestore をアプリから直接読んで、変わったらすぐ出す：ログインは API のトークンだけで（ADR 0009）、アプリは Firestore の認証を持たない。入れるには認証とセキュリティルールを足すことになる。

## 割り切っていること

- ほかの端末でためたメモは、すぐには出ない。読み直したときかアプリに戻ってきたときに出る。
- 2つの端末で同じメモを同時に書き直したら、後で保存した方が残る。
- 書き直している間にほかの端末でそのメモを消したり記録したりしていたら、保存したときに知らせ、メモを読み直す。
