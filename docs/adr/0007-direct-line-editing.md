# 0007 ノートを行ごとに直接編集でき、書いた行も衝突検知にかける

- 日付：2026-11-08
- 状態：採用

## 背景

- これまでノート（画面上の呼び名。コードでは `manual`）を変えられるのは、口頭で言われたことを記録して差分を反映するときだけだった。
- しかしこのアプリは、マニュアルに限らず、自分用のメモやコーディング規約などの汎用のノートに「論理の食い違いに気づく」機能が付いたものとして使いたい。そのためには、エディタとして直接書き足せる必要がある。
- 直接書いた行が、前に書いた行や教わったことと食い違うことも起きる。食い違いに気づくのがこのアプリの強みなので、直接書いた行も衝突検知にかける。

## 決定

1. **行ごとに編集する**
   - ノート画面で行を押すと、その場で書き換え・下に行を足す・消すができる。末尾には「行を書き足す」を置く。全文を1つの欄で編集する形にはしない。
   - 食い違っている行は、これまで通り押すと確認リストを開く（その場で解決させない）。確定してから編集する。
2. **直接の編集も土台の記録とパッチにする（ADR 0001 のまま）**
   - 編集1回を、発言者「自分」・`fromEdit: true` の記録と、反映済みのパッチ1件として残す（`POST /manuals/:id/edits`）。確定の答えを発言として残すのと同じ考え方で、行ごとの出どころ（誰がいつ書いたか）が引ける。
   - 行を消せるよう、パッチに `delete` を足す。
   - 直接書いた行は本人の文なので、画面では付箋・記録の数・左余白の色線・発言者の印に出さない。（2026-11-09 追記：ノートを共有された人が直した行は、本人の文ではないので、左余白の色線と発言者の印を出す。付箋・記録の数には入れない。ADR 0013）
3. **書いた行も衝突検知にかける。ただし編集とは別に呼ぶ**
   - 編集は先に反映して返し、アプリがそのあと `POST /manuals/:id/patches/:pid/check` を呼ぶ。Gemini は1回10秒前後かかるので、編集のたびに待たせない。
   - 分類には、書いた行を「末尾への追記」として、その行以外の全行と確定済みの記録と一緒に渡す。書き換える前の行は本人が直したので、もう残っておらず相手にならない。分類のプロンプトは変えていない。（2026-11-10 追記：確定済みの行を書き換えたときは、書き換える前の行を元の位置に確定の出どころ付きで渡し、前の確定を相手にする。#86）
   - 見出し（`## `）と削除は主張ではないので確かめない。（2026-11-09 追記：見出しはすべての深さに、区切り線も同じ扱いに広げた。ADR 0009）
4. **食い違いを確定すると、2行を1行にまとめる**
   - 口頭の記録では、矛盾したパッチは反映されずに残る。直接書いた行はもう反映済みなので、確定したときに書いた行を消し、衝突相手の行を確定した内容にする。

## 理由

- 行単位のパッチと出どころ（ADR 0001）をそのまま使えるので、土台の形も衝突検知のプロンプトも変えずに済む。
- 書いた行をすぐ画面に出せないと、エディタとして使えない。

## 制約・既知の問題

- 同じ文字列の行が複数あると、最初の行が編集の対象になる（ADR 0001 と同じ）。
- 先頭より前には行を足せない（見出しや行の「下に行を足す」と、末尾への書き足しだけ）。
- 確かめる前に画面を閉じると、その編集は確かめられないまま残る。
- PR #26（差分化と分類を1回の Gemini 呼び出しにまとめる）は、分類だけを呼ぶ `checkWithGemini` を消す。あちらを先に取り込むなら、直接編集の確かめには分類だけの呼び出し（`checkRules` と `manualContext` を使う）を戻す必要がある。

## 追記（2026-11-10）：保存を待たずに出し、Enter で続けて書く（設計書 0020 の C1）

- 保存したら、アプリの中でサーバーと同じ当て方（`history.dart` の `patchLines`）で行を書き換え、応答を待たずに出す。`POST /manuals/:id/edits` は裏で、ノートごとに1本ずつ書いた順に送る。送っている間だけ、題名の下に「保存しています…」を出す。
- 発言と差分の ID はアプリが作って送る（`utteranceId`・`patchId`。英数字で始まる16〜64文字）。そのノートの今ある発言・差分と同じ ID なら 409 で断る（保存は上書きなので、共有された人がほかの人の記録を書き換えられないように）。省けば今までどおりサーバーが作る。
- 古い応答で新しい状態を上書きしない。編集の応答は、送っていない編集が残っている間と、編集欄を開いている間は画面に入れず、どちらも済んでから最後の応答を入れる（欄は行の番号で場所を覚えるので、ほかの人の編集で行がずれると別の行を書き換える）。欄は、ほかの画面やダイアログへ移るときに閉じる。確定などほかの書き込みの応答はすぐ入れ、まだ応答に入っていない自分の編集はその上に重ねて出す。（2026-11-10 追記：応答も裏の取り直しも、アプリの store を通して入れるようにした。欄を開いている間は、裏の取り直しも含めてどれも取っておく。送っていない編集がある間に取っておくのは、編集の応答と裏の取り直しで、確定などほかの書き込みの応答は今までどおりすぐ入れる。ADR 0020）
- 欄で Enter を押すと保存し、書いた行のすぐ下に次の行の欄を開く。空のまま Enter か Esc で閉じる。「保存する」は保存して閉じる。
- 確かめ（決定 3）は、その編集が届いてから呼び、1本ずつ順に送る。編集の送信とは別の列にし、数秒かかる確かめの後ろで編集を待たせない。確かめの応答は全体を差し替えず、その確認1件だけを今の状態に足す。
- 届かなかったら戻す。ほかの人が先に同じ行を直していたら、今の選ぶダイアログ（ADR 0016）を出す。そのほかの失敗では、その編集と後ろに積んでいた編集を戻し、何行戻したかを出す。欄を閉じていれば、届かなかった行の文面をその場所の欄に入れ直す。
- アプリの中で画面を移っても、積んだ編集と確かめは送り切る。届く前にタブを閉じると、その編集は残らない。
