# 0013 ノートをほかのアカウントに共有し、行を直してもらう

- 日付：2026-11-09
- 状態：採用（共有された人ができることは ADR 0016 で置き換えた。消す以外は持ち主と同じにした）

## 背景

- ノートは人ごとに分かれていて（ADR 0009）、本人しか見られない。
- 新人が書いたノートを、教えてくれる店長や先輩に見てもらい、間違いをその場で直してもらいたいことがある。直してもらった行も、ほかの行や確定済みの記録と食い違えば、確認リストに入れたい。
- spec では共有を「組織側の機能」として後回しにしていた。今回の共有は、新人が自分で選んで教える側に見せるもので、上司が導入して配る機能ではない。

## 決定

1. **相手の指定**：ノートの持ち主が、ノートのページの「共有」から相手のログイン ID を入れて足す。招待や承認は無く、相手が次にサイドバーを読み込むと「共有されたノート」に出る。無い ID・自分の ID はエラーにする。持ち主は相手を外せる。外すと相手はすぐ読めなくなる。
2. **共有された人ができること**：ノートを見る（本文・履歴・確認リスト）ことと、行を直接編集する（ADR 0007 と同じ流れ。編集のあとの衝突検知も同じ）ことだけ。
3. **持ち主だけができること**：言われたことの記録、書き込む前の確認（書き込む・書き込まない・言われたことを直す）、確定、共有の相手を足す・外す、そのほかの操作。
4. **編集した人を残す**：共有された人の編集は、ADR 0007 と同じ `fromEdit: true` の記録とパッチにし、発言者（`speaker`）にその人の名前（ADR 0010。決めていなければ ID）、`editedBy` にその人のログイン ID を入れる。持ち主の編集は今までどおり「自分」で、`editedBy` は付けない。画面では、共有された人が直した行に、口頭で変わった行と同じ発言者の印と左余白の色線を付ける（本人の文ではないため）。
5. **認可は API で確かめる**：ノートを読む関数（`load`）は、既定では持ち主にだけ許す。共有された人にも許すのは `GET /manuals/:id`・`POST /manuals/:id/edits`・`POST /manuals/:id/patches/:pid/check` の3つだけで、ほかの呼び出しは今までどおり持ち主でなければ 404 になる。

## データの持ち方

- 持ち主の側：`users/{持ち主}/manuals/{ノート}/shares/{相手の ID}`（`{id, createdAt}`）。誰に共有しているかの正はこちら。土台の `utterances`・`patches` と同じく、ノートの下のコレクションとして既存の `list`・`put`・`remove` で読み書きする。
- 相手の側：`users/{相手}/shared/{ノート}`（`{id, ownerId, createdAt}`）。相手のサイドバーに並べるためと、相手が `/manuals/:id` を呼んだときに持ち主を引くための索引。
- 共有された人が読むときは、相手の側の索引で持ち主を引き、持ち主の側の `shares` に自分がいることを確かめてから持ち主のノートを読む。
- 足すときは持ち主の側を先に、外すときは相手の側を先に書く。途中で失敗しても、残るのは「持ち主の側にはあるが相手の側に無い」形だけになり、相手が読めてしまう形は残らない（読むときは両方を確かめる）。順番を入れ替えないこと。
- ノートの API の応答に `owner`（持ち主の ID）と `sharedBy`（共有されたノートなら持ち主の ID と名前、自分のノートなら null）を足す。
- 相手の側の索引はノートの ID だけで引く。ノートの ID はランダムな UUID で、人をまたいでも重ならない（起動時のデモのノート `demo-kitchen` などは `demo` にしか無い）。もし相手が同じ ID のノートを持っていても、相手には自分のノートが出るだけで、ほかの人のノートは読めない。

## 理由

- 人ごとに分けたデータ（ADR 0009）をそのまま使える。ノートを人の外の場所に移すと、読み書きのすべての呼び出しと保存先を変えることになる。
- 「自分に共有されたノート」を持ち主の側から探すには、コレクショングループのクエリとそのインデックスが要る。相手の側に索引を置けば、ドキュメントを1件読むだけで済み、Terraform を変えずに済む。
- 既定を持ち主だけにしておけば、共有された人に許す呼び出しを書き忘れても、許しすぎる側には倒れない。

## 採らなかった案

- 共有の記録を最上位のコレクション（`shares/{…}`）に置き、相手の ID で検索する：1か所で済むが、毎回の読み込みに検索が入り、ノートの ID が人ごとにしか重ならないことを ID の作り方でかばう必要がある。
- ノートのドキュメントに共有の相手の一覧を持たせる：土台の `Manual` の形が共有の都合で変わる。
- 見るだけの共有：教える側が間違いを直せないと、狙い（教える側に直してもらう）を果たせない。

## 割り切っていること

- 相手の画面には、持ち主が足した時点では出ない。相手がページを読み込み直すかサイドバーが読み直されたときに出る（配信の仕組みは作らない）。（2026-11-10 追記：サイドバーは何かを書くたびには読み直さなくなった。相手がアプリを開いたときか、アプリに戻ってきたときに出る。ADR 0021）
- 共有された人には、そのノートの「あとで確認」の件数を数えない（サイドバーの合計・入力ページ・「あとで確認」のページに出さない）。確定は持ち主がするため。
- 共有された人の名前は、編集したときのものを残す。後で名前を変えても、前の編集の発言者は変わらない。
- ノートを消す操作は今も無い。足すときは持ち主だけに許す。
- 無い ID をエラーにするので、ログインした人なら、ある ID かどうかを確かめられる。アカウントはこちらで配った人だけなので許す。
