# 0005 入力をアプリ起動時の専用画面に一本化し、ファイル・音声と複数マニュアルへの振り分けに対応する

- 日付：2026-11-08
- 状態：採用

## 背景

- これまでは「マニュアル一覧から1冊を開く → マニュアル画面の下部にある1行の入力欄にテキストを打つ」流れだった。
- しかし現場の新人は、口頭で教わったことや渡された紙メモ・PDF・録音データが「どのマニュアルのどの節に当たるか」を先に探したいわけではなく、アプリを開いてすぐ記録したい。また、1回の指示が複数のマニュアル（例：仕込みマニュアルとホール接客マニュアル）にまたがることもある。

## 決定

1. **入力専用ページをアプリの最初の画面にする**
   - アプリを開くと最初に入力ページが出る。上部バーの「マニュアルを確認」からマニュアル一覧（`HomeScreen`）→ 各マニュアルの閲覧画面（`ManualScreen`）へ進む。
   - 入力ページには、入力操作（テキスト・ファイルアップロード［PDF／画像］・音声の録音）に加えて、「あとで確認（確認リスト）」への導線と最近の記録を置く。
   - `ManualScreen` 下部にあった入力欄は廃止し、入力は入力専用ページに一本化する。
2. **ファイル（PDF／画像）と音声は、バックエンドの前段でテキストに変換する**
   - ファイルや音声はバックエンドで Gemini に渡してテキスト（言われた内容）へ変換し、そのままテキスト入力と同じ後続処理へ流す。
   - 土台のデータ構造（`Utterance.text`・`Patch`、ADR 0001）や、差分化・衝突検知のモジュール（`patchify`・`check`、ADR 0002）、評価セット（`eval/`）は変更しない。
3. **複数マニュアルへの一括入力と自動振り分け**
   - 利用者は対象のマニュアルを選ばずに一括で入力する。
   - バックエンドで登録済みの全マニュアルから関係するマニュアル（複数にまたがる場合はそれぞれ）を判定し、対象のマニュアルごとに `patchify` → `check` を実行して保存する。
   - 処理が完了したら、そのまま画面上で差分の確認モーダルを出す。

## 理由

- 入力の手間（「どのマニュアルか探す」「手で文字に起こす」）を減らし、「入力の手間を払う人と得をする人が同じ」というプロダクトの前提（`docs/spec/spec.md`）を守るため。
- マルチモーダル入力の扱いを前段のテキスト変換に閉じ込めることで、既存の土台・衝突検知・評価の仕組みを壊さずに拡張できるため。

## 実装で決めたこと

- 入力ページは `POST /utterances` を呼ぶ。前段（`api/src/intake.ts`）で、ファイル・録音の書き起こし（`transcribe`）と、全マニュアルの全文を載せた振り分け（`route`）を行い、選ばれたマニュアルごとに既存の `patchify` → `check` を通す。
- 振り分けでどのマニュアルにも当たらなければ何も保存せず、読み取った文面を返す。利用者が記録先を選ぶと、その文面と `manualIds` で送り直す（ファイル・録音は読み直さない）。
- 複数のマニュアルに当たったときは、差分の確認モーダルをマニュアルごとに順に出す。入力ページの「あとで確認」は、確認リストがマニュアルごとなので、件数とともに1冊ずつ並べる。
- 受け付ける形式は PDF・PNG・JPEG・WebP・HEIC・WAV（録音）で、合わせて 10MB まで（Gemini に1回で渡せる大きさに収めるため）。

## 追加したライブラリ

- [file_picker](https://pub.dev/packages/file_picker)（13.3.2、MIT）：Web でファイルを選び、中身を読むため。
- [record](https://pub.dev/packages/record)（7.1.2、BSD-3-Clause）：Web でマイクから録音するため。Gemini が読める WAV（16kHz・モノラル）を Web で直接作れる。
