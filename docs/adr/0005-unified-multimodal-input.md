# 0005 入力をアプリ起動時の専用画面に一本化し、ファイル・音声と複数マニュアルへの振り分けに対応する

- 日付：2026-11-08
- 状態：採用（振り分け `route` と、マニュアルごとの `patchify` → `check` は、ADR 0006 で1回の `assess` にまとめた）

## 背景

- これまでは「マニュアル一覧から1冊を開く → マニュアル画面の下部にある1行の入力欄にテキストを打つ」流れだった。
- しかし現場の新人は、口頭で教わったことや渡された紙メモ・PDFが「どのマニュアルのどの節に当たるか」を先に探したいわけではなく、アプリを開いてすぐ記録したい。また、1回の指示が複数のマニュアル（例：仕込みマニュアルとホール接客マニュアル）にまたがることもある。
- さらに口頭の指導では、「今から大事なことを言うから録音して」と予告されることはなく、**言われた後に「今のは残しておきたい」と気づく**。また、教わっている最中にスマホ画面を見て発言者を入れたり差分を確認したりする余裕はない。そのため、言われる前に録音ボタンを押す方式ではなく、常時メモリ上に直前の音声を保持して**現場では「言われた後に大きなボタンを押すだけ」で文字起こしメモとしてストックし、あとで時間があるときに発言者や文面を整えて差分化する2段階の体験**と、最初から自分の言葉でメモを吹き込める音声入力の2つに分ける必要がある。

## 決定

1. **アプリの最初の画面は入力ページにし、リワインド（現場での待ち受け・切り出し）は題名の右のトグルで ON／OFF する**
   - アプリを開くと最初の画面（入力ページ、`InputScreen`）が出る。題名「言われたことを記録」の右に「リワインド」のトグル（`MoonSwitch`）を置き、ON にすると書く欄の所が待ち受けの面（`RewindPanel`）に替わる。OFF にすると書く欄に戻る。
   - リワインドは勤務中ずっと ON にして、口頭の指示を取りこぼさないためのもの。現場で待ち受ける間と、あとで整理する間は同時に使わないので、タブで並べず、トグルで切り替える。タブだと隣の「整理・入力」に誤って触れただけで待ち受けが止まり、直前60秒も消えるため。
   - 前は別のページにしていたが、サイドバーまで消えて画面が大きく変わったように見えたので、同じページの中で替える。題名・トグル・サイドバー・最近の記録の位置は変えず、書く欄とあとで確認の所だけを、待ち受けの面と未整理メモにする。
   - 上部バーの「マニュアルを確認」からマニュアル一覧（`HomeScreen`）→ 各マニュアルの閲覧画面（`ManualScreen`）へ進む。
   - 入力ページには、リワインドでストックした「切り出したメモ（未整理）」の一覧、音声入力つきテキスト欄・ファイルアップロード（PDF／画像）に加えて、「あとで確認（確認リスト）」への導線と最近の記録を置く。
   - `ManualScreen` 下部にあった入力欄は廃止し、入力は最初の画面に一本化する。
2. **音声の取り込みは「リワインドモードでの1タップ切り出し（即時ストック → あとで差分化）」と「テキスト欄への音声入力」の2系統にする（「今から録音して添付する」ボタンは置かない）**
   - **リワインドモード（常時待ち受け・遡り録音）**：
     - トグルを ON にしている間だけ待ち受ける。ON にしたときにマイク許可と待ち受けを開始し、OFF にすると止める。
     - 待ち受け中は 16kHz・モノラル・16bit PCM のストリームを受け取り、直前60秒を端末メモリ上のリングバッファ（`RingBuffer`）だけで上書き保持し続ける。ディスクやネットワークには一切書き出さない。
     - 待ち受け中は画面上に「端末内で直前60秒を保持中（送信していません）」の案内と音量インジケータを常時表示し、プライバシーの安心感を伝える。
     - 画面には視線を落とさなくても押しやすい大きな主ボタン「直前の発話を残す」を置く。言われた後にボタンを押すと、音量ベースの簡易 VAD（`EnergyVad`）で話し終わり（無音1秒継続、最大延長15秒）まで録音を延ばし、押した時刻に最も近い発話のかたまり（無音区切り1.5秒、前後300msパディング）だけを WAV にして切り出す。発話が検出されなければ送信せず「声が入っていませんでした」と知らせる。
     - **その場では差分化やモーダル表示を行わず、待ち受けを止めない（連続で何度でも押せる）**。切り出した WAV はバックグラウンドで `POST /listen` へ送って Cloud Speech-to-Text v2 で文字に起こし、切り出し時刻とともに端末内（`shared_preferences`）の「未整理メモ」にストックする。待ち受けの面の下に未整理メモを並べ、ストック状況を確認できる。
     - **あとで時間があるときにリワインドを OFF にして**、ストックされた未整理メモを「入力欄に入れる」でテキスト入力欄に流し込む（複数のメモを続けて流し込み1つの指示にまとめることもできる）。口頭で抜けていた主語や誤変換、発言者名（「田中さんから」など）を補ってから「差分を作る」で `POST /utterances` へ送り、完了後に差分の確認モーダル（`ReviewDialog`）を開く。差分を作成したメモ（または不要として削除したメモ）は未整理メモから消す。
   - **テキスト欄の音声入力（ディクテーション）**：
     - Google 検索の音声入力と同じく、テキスト入力欄の中にマイクのボタンを置く。押して話すと、話している途中から書き起こした文字が入力欄に出て、話し終わると自動で止まる。利用者はテキストを手直ししたり PDF・画像を添えたりしてから「差分を作る」で送信できる。
3. **音声は Cloud Speech-to-Text v2、ファイル（PDF／画像）は Gemini で前段テキスト化する**
   - 音声（リワインドの切り出し WAV・テキスト欄の音声入力の両方）は、バックエンドで **Cloud Speech-to-Text v2**（日本語 `ja-JP`、自動句読点付与、登録マニュアルの語句からのフレーズヒント適応）を呼んでテキストに起こす。リワインドの切り出し WAV は `POST /listen` でテキスト化だけを行い、Gemini は呼ばない。
   - ファイル（PDF／画像）は、バックエンドの `POST /utterances` で **Gemini** に渡してテキスト（言われた内容）に起こす。
   - 変換後のテキストをそのままテキスト入力と同じ後続処理へ流す。雑談の除外や指示の抽出は既存の `route`・`patchify` に任せる。
   - 土台のデータ構造（`Utterance.text`・`Patch`、ADR 0001）や、差分化・衝突検知のモジュール（`patchify`・`check`、ADR 0002）、評価セット（`eval/`）は変更しない。
4. **複数マニュアルへの一括入力と自動振り分け**
   - 利用者は対象のマニュアルを選ばずに一括で入力する。
   - バックエンドで登録済みの全マニュアルから関係するマニュアル（複数にまたがる場合はそれぞれ）を判定し、対象のマニュアルごとに `patchify` → `check` を実行して保存する。
   - 処理が完了したら、そのまま画面上で差分の確認モーダルを出す。

## 理由

- 口頭指導は予告なく始まり、かつ指導の最中に発言者入力や差分の確認をする余裕はないため、現場では「言われた後に大きなボタンを押すだけで文字起こしメモとしてストック（常時待ち受け＋簡易VAD）」し、あとで落ち着いて文面や発言者を整えてから差分化する2段階の流れが現場の体験に合うため。また、最初から自分で整理して吹き込む用途にはテキスト欄への音声入力が適しており、用途ごとに分けることで中途半端な手間をなくせるため。
- 未整理メモは文字起こし後の短いテキストと時刻だけなので端末内（`shared_preferences`）で十分に保持でき、土台（Firestore のデータ構造）を変えずに済むため。
- 入力の手間（「どのマニュアルか探す」「手で文字に起こす」）を減らし、「入力の手間を払う人と得をする人が同じ」というプロダクトの前提（`docs/spec/spec.md`）を守るため。
- 音声とファイルの扱いを前段のテキスト変換に閉じ込めることで、既存の土台・衝突検知・評価の仕組みを壊さずに拡張できるため。

## 実装で決めたこと

- リワインドの切り出しは `POST /listen` を呼び、Speech-to-Text（`listen`）で書き起こした文面だけを返して端末内の未整理メモ（`shared_preferences`）に保存する。
- 話し終わりを待っている間（最大15秒）は切り出しボタンを押せない。書き起こしは待たないので、切り出し終われば続けて押せる。
- 書き起こせなかった（聞き取れない・通信の失敗）ときは、メモを作らずに知らせる。音声は端末にも残さない。
- 未整理メモから記録するときの「言われた日」は、入力欄に入れたメモのうち一番古い切り出しの日にする。後日まとめて整理しても日付がずれないため。
- アプリはいつも入力ページから開く。前回リワインドを ON にしたまま閉じていても、リワインドからは始めない。ブラウザは操作の前にマイクを開けない（音声の処理が止まったまま始まる）ので、トグルを押した操作で待ち受けを始めるため。
- 入力ページの「差分を作る」は `POST /utterances` を呼ぶ。前段（`api/src/intake.ts`）で、PDF・画像は Gemini（`transcribe`）で書き起こし、全マニュアルの全文を載せた振り分け（`route`）を行って、選ばれたマニュアルごとに既存の `patchify` → `check` を通す。
- テキスト欄の音声入力は、WebSocket（`/dictation`）で PCM を少しずつ送り、Speech-to-Text v2 のストリーミング（途中の結果つき）で返ってきた文面をそのまま入力欄に出す。書き起こすだけで記録はしない。ブラウザの WebSocket はヘッダーを付けられないので、合言葉はこの口だけクエリでも受ける。
- 音声入力の話し終わりはアプリの `EnergyVad` で決める。話したあと無音が1.5秒続く・話し出さないまま8秒たつ・60秒に達する、のどれかで止める。
- Speech-to-Text は無音を「はい。」などと書き起こすことがあるので、音声入力は声が聞こえるまで送らない。聞こえたら直前0.5秒からさかのぼって送り、聞こえないまま止まったら何も送らずに知らせる。
- Speech-to-Text は `chirp_2`（`us-central1`）で呼ぶ。`chirp_2` は `global` では使えないため。フレーズヒントは登録済みの全マニュアルの見出しと各項目の頭の語にする（行の途中で切れなかった8文字を超える語句は除く）。
- 常時待ち受けの切り出しは同期の書き起こし（60秒まで）で読むので、バックエンドで WAV の末尾60秒だけを渡す。
- 常時待ち受けの声の判定（`EnergyVad`）は、20ms ごとの音量（RMS）だけで行う。声の合計が200ms に満たないかたまりは物音とみなして除く。
- リワインドの大きなボタンは常に1つにし、状態に合わせて文字と動きを変える：マイクの準備中は「マイクを準備しています…」（押せない）、待ち受け中は「いま言われたことをメモする」、押した後は「話し終わるのを待っています…」（押せない）、マイクを開けなかった・止まったときは「待ち受けを始める」。現場で画面を見ずに押すので、ボタンの場所を変えず、大きな丸いボタンにする。未整理メモは待ち受けの面の下に置き、メモが増えてもボタンが動かないようにする。
- マイクを開けなかった（許可されていない）ときは、ボタンの上に「ブラウザの設定でマイクを許可してから、もう一度押してください」と出す。画面を押すたびに開き直して同じ失敗を繰り返さない。
- 未整理メモは入力ページが持ち、待ち受けの面は書き起こせたメモを入力ページに渡す。書き起こしを待つ間にリワインドを OFF にしても、届いたメモを取りこぼさないため。
- 未整理メモの付箋を押すと、その場で書き直せる（「保存する」「やめる」）。誤変換をリワインドの合間にも直せるようにするため。入力欄に入れるのは付箋の「入力欄に入れる」で行う。
- リワインドを ON にしたままサイドバーなどからほかのページへ移っても、入力ページは裏に残るので待ち受けは続く。止めるのはトグルを OFF にしたときだけにする。誤って触れて直前60秒が消えないようにするため。
- 振り分けでどのマニュアルにも当たらなければ何も保存せず、読み取った文面を返す。利用者が記録先を選ぶと、その文面と `manualIds` で送り直す（ファイル・録音は読み直さない）。
- 複数のマニュアルに当たったときは、差分の確認モーダルをマニュアルごとに順に出す。入力ページの「あとで確認」は、確認リストがマニュアルごとなので、件数とともに1冊ずつ並べる。
- 受け付ける形式は PDF・PNG・JPEG・WebP・HEIC・WAV（録音）で、合わせて 10MB まで（Gemini に1回で渡せる大きさに収めるため）。
- 1MB を超える PNG・JPEG・WebP は、アプリで長い辺 2000px の JPEG（品質 0.85）に縮めてから添える。スマホの写真は1枚3〜8MBあり、2枚で上限に届くため。HEIC は Safari 以外のブラウザで描けないので、縮めずにそのまま送る（#31）。
- ファイルは「ファイルを添える」のほか、スマホでは「写真を撮る」でカメラを直接開き、PC では画面への貼り付けとドロップでも添えられる。画像はサムネイル、PDF は名前で見せる（#31）。
- 声とみなす音量は、直前10秒の音量の下から1割を周りの騒音とみなし、その3倍（約 +10dB）に合わせる（静かな所では既定の RMS 500 より下げない）。換気扇や食洗機の音が続く厨房で、ずっと「話している」と判定して押すたびに15秒待たせないため（#30）。
- 常時待ち受け中は Screen Wake Lock で画面を点けたままにする。スマホのブラウザは画面が消えるとマイクを止めるため。タブが隠れると外れるので、見えるようになったら取り直す。それでも止まったとき（マイクの流れが終わった、または画面に戻って2秒たっても音が届かない）は、ボタンの上に「待ち受けが止まっていました。押すと再開します」と出し、同じボタンで再開する（#30）。

## 追加したライブラリ

- [file_picker](https://pub.dev/packages/file_picker)（13.3.2、MIT）：Web でファイルを選び、中身を読むため。
- [record](https://pub.dev/packages/record)（7.1.2、BSD-3-Clause）：Web でマイクから録音するため。16kHz・モノラル・16bit の PCM をストリームで受け取れるので、常時待ち受けのリングバッファと音声入力のストリーミングをアプリで作れる。
- [@google-cloud/speech](https://www.npmjs.com/package/@google-cloud/speech)（8.2.1、Apache-2.0）：Cloud Speech-to-Text v2 を ADC（Cloud Run ではサービスアカウント）で呼ぶため。Google 公式のクライアント。
- [ws](https://www.npmjs.com/package/ws)（8.22.1、MIT）：音声入力の WebSocket を受けるため。`@hono/node-server` 2.x の WebSocket 対応がこれを使う。
- [web_socket_channel](https://pub.dev/packages/web_socket_channel)（3.0.3、BSD-3-Clause）：アプリから音声入力の WebSocket につなぐため。Dart チームの公式パッケージ。
- [web](https://pub.dev/packages/web)（1.1.2、BSD-3-Clause）：待ち受け中に画面を点けたままにし（Screen Wake Lock）、タブが見えるようになったことを知るため。画像の縮小（canvas）・カメラ・貼り付けとドロップにも使う。Dart チームの公式パッケージで、これまでも他のパッケージ経由で入っていた。
