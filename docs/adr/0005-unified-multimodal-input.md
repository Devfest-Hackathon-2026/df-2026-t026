# 0005 入力をアプリ起動時の専用画面に一本化し、ファイル・音声と複数マニュアルへの振り分けに対応する

- 日付：2026-11-08
- 状態：採用

## 背景

- これまでは「マニュアル一覧から1冊を開く → マニュアル画面の下部にある1行の入力欄にテキストを打つ」流れだった。
- しかし現場の新人は、口頭で教わったことや渡された紙メモ・PDFが「どのマニュアルのどの節に当たるか」を先に探したいわけではなく、アプリを開いてすぐ記録したい。また、1回の指示が複数のマニュアル（例：仕込みマニュアルとホール接客マニュアル）にまたがることもある。
- さらに口頭の指導では、「今から大事なことを言うから録音して」と予告されることはなく、**言われた後に「今のは残しておきたい」と気づく**。そのため、言われる前に録音ボタンを押す方式ではなく、常時メモリ上に直前の音声を保持して「言われた後にボタンを押すだけ」で切り出せる体験と、後から自分の言葉でメモを吹き込める音声入力の2つに分ける必要がある。

## 決定

1. **入力専用ページをアプリの最初の画面にする**
   - アプリを開くと最初に入力ページが出る。上部バーの「マニュアルを確認」からマニュアル一覧（`HomeScreen`）→ 各マニュアルの閲覧画面（`ManualScreen`）へ進む。
   - 入力ページには、入力操作（常時待ち受けからの切り出しボタン・音声入力つきテキスト欄・ファイルアップロード［PDF／画像］）に加えて、「あとで確認（確認リスト）」への導線と最近の記録を置く。
   - `ManualScreen` 下部にあった入力欄は廃止し、入力は入力専用ページに一本化する。
2. **音声の取り込みは「常時待ち受けからの1タップ切り出し」と「テキスト欄への音声入力」の2系統にする（「今から録音して添付する」ボタンは置かない）**
   - **常時待ち受け（遡り録音）**：
     - 入力ページに常時待ち受けの ON／OFF 切り替えを置く。既定は OFF とし、ON にしたときにマイク許可と待ち受けを開始する（ON／OFF の選択はブラウザの `shared_preferences` に記憶し、次回以降は操作時に再開する。いつでも一時停止できる）。
     - 待ち受け中は 16kHz・モノラル・16bit PCM のストリームを受け取り、直前60秒を端末メモリ上のリングバッファ（`RingBuffer`）だけで上書き保持し続ける。ディスクやネットワークには一切書き出さない。
     - 待ち受け中は画面上に「端末内で直前60秒を保持中（送信していません）」の案内と音量インジケータを常時表示し、プライバシーの安心感を伝える。
     - 言われた後に切り出しボタンを押すと、音量ベースの簡易 VAD（`EnergyVad`）で話し終わり（無音1秒継続、最大延長15秒）まで録音を延ばし、押した時刻に最も近い発話のかたまり（無音区切り1.5秒、前後300msパディング）だけを WAV にして切り出す。発話が検出されなければ送信せず「声が入っていませんでした」と知らせる。
     - 切り出した WAV は添付チップにはせず、そのまま自動で `POST /utterances` へ送って差分作成まで進める（1タップ体験）。会話の音声には発言者名が入らないことが多いため、完了後に開く差分の確認モーダル（`ReviewDialog`）で発言者を補えるようにする。
   - **テキスト欄の音声入力（ディクテーション）**：
     - テキスト入力欄に「音声入力」ボタンを付ける。押して話し、止めると録音した WAV をバックエンドの文字起こし API に送り、返ってきたテキストを入力欄に追記する。利用者はテキストを手直ししたり PDF・画像を添えたりしてから「差分を作る」で送信できる。
3. **音声は Cloud Speech-to-Text v2、ファイル（PDF／画像）は Gemini で前段テキスト化する**
   - 音声（常時待ち受けの切り出し WAV・テキスト欄の音声入力 WAV の両方）は、バックエンドで **Cloud Speech-to-Text v2**（日本語 `ja-JP`、自動句読点付与、登録マニュアルの語句からのフレーズヒント適応）を呼んでテキストに起こす。
   - ファイル（PDF／画像）は、バックエンドで **Gemini** に渡してテキスト（言われた内容）に起こす。
   - 変換後のテキストをそのままテキスト入力と同じ後続処理へ流す。雑談の除外や指示の抽出は既存の `route`・`patchify` に任せる。
   - 土台のデータ構造（`Utterance.text`・`Patch`、ADR 0001）や、差分化・衝突検知のモジュール（`patchify`・`check`、ADR 0002）、評価セット（`eval/`）は変更しない。
4. **複数マニュアルへの一括入力と自動振り分け**
   - 利用者は対象のマニュアルを選ばずに一括で入力する。
   - バックエンドで登録済みの全マニュアルから関係するマニュアル（複数にまたがる場合はそれぞれ）を判定し、対象のマニュアルごとに `patchify` → `check` を実行して保存する。
   - 処理が完了したら、そのまま画面上で差分の確認モーダルを出す。

## 理由

- 口頭指導は予告なく始まるため、言われた後に押すだけで残せる「常時待ち受け（リングバッファ＋簡易VAD）」が現場の体験に合うため。また、自分で整理して吹き込む用途にはテキスト欄への音声入力が適しており、2つに分けることで「録音ファイルを添付してから送信する」中途半端な手間をなくせるため。
- 入力の手間（「どのマニュアルか探す」「手で文字に起こす」）を減らし、「入力の手間を払う人と得をする人が同じ」というプロダクトの前提（`docs/spec/spec.md`）を守るため。
- 音声とファイルの扱いを前段のテキスト変換に閉じ込めることで、既存の土台・衝突検知・評価の仕組みを壊さずに拡張できるため。

## 実装で決めたこと

- 入力ページは `POST /utterances` を呼ぶ。前段（`api/src/intake.ts`）で、ファイル・録音の書き起こし（`transcribe`）と、全マニュアルの全文を載せた振り分け（`route`）を行い、選ばれたマニュアルごとに既存の `patchify` → `check` を通す。
- 振り分けでどのマニュアルにも当たらなければ何も保存せず、読み取った文面を返す。利用者が記録先を選ぶと、その文面と `manualIds` で送り直す（ファイル・録音は読み直さない）。
- 複数のマニュアルに当たったときは、差分の確認モーダルをマニュアルごとに順に出す。入力ページの「あとで確認」は、確認リストがマニュアルごとなので、件数とともに1冊ずつ並べる。
- 受け付ける形式は PDF・PNG・JPEG・WebP・HEIC・WAV（録音）で、合わせて 10MB まで（Gemini に1回で渡せる大きさに収めるため）。

## 追加したライブラリ
