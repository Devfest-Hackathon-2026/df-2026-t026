# 0022 ノートを、1行を1まとまりとするマークダウンとして描く

- 日付：2026-11-09
- 状態：採用
- 番号：書いたときは 0009 だったが、ログインの ADR（0009-login-with-issued-accounts）と番号が重なっていたので 0022 に改めた（2026-11-10）。2026-11-10 より前のコミット・PR で「ADR 0009」がマークダウンの話なら、この ADR のこと

## 背景

- ノートは `## ` を見出し、`- ` を項目として描き、それ以外は書いたままの文字で出していた。「ノートを作る」画面でも「『## 見出し』『- 項目』の形にすると読みやすい」と案内していた。
- 見た目も案内もマークダウンなので、利用者はマークダウンだと思って書く。Notion や ChatGPT から貼ると、`**太字**`・`### 小見出し`・`1. 番号` が記号のまま出ていた。
- 差分は行の文字列で当て（ADR 0001）、編集も行ごとに行う（ADR 0007）。この単位は変えたくない。

## 決定

1. **1行を1まとまりとして描く**。前後の行は見ずに、その行だけで決まる書き方を読む。
   - 見出し `# ` 〜 `###### `：`#` は `display`、`##` は `title`、`###` 以降は `heading` の大きさ。履歴の差分のような一覧では、どの深さも `heading` にする
   - 箇条書き `- ` `* ` `+ ` は「・」、番号 `1. ` `1) ` は書いた通り
   - 行頭の空白（2文字で1段）は入れ子として下げる。引用 `> ` は1段下げて薄い文字にする
   - 区切り線 `---` `***` `___` は罫線にする
   - 行の中の太字・斜体・`コード`・リンク・取り消し線
2. **複数行にまたがる書き方は読まない**。表・コードブロックは記号のまま出す。改行1つの行を1段落にまとめる決まりにも従わず、1行は1行のまま出す。
3. **見出しと区切り線は主張ではない**。書き換えや衝突の相手にせず（`api/src/gemini.ts` の `isItem`）、直接書いても確かめない。ADR 0007 の「見出し（`## `）」はすべての深さの見出しと区切り線に広げる。
4. **行頭の空白を残す**。入れ子を直接編集で保てるよう、編集の本文はアプリ・API とも行末の空白だけを落とす。
5. **文の中に出すとき**（確認リストの「ノートの行 ／ 言われた行」、通知など）は、行頭と行の中の印を外した文字にする（`plain`）。
6. **行の中の書き方の読み取りには `markdown` パッケージ（7.3.1、BSD-3-Clause）を使う**。Dart チームが保守しており、太字の入れ子やエスケープを自前で書かずに済む。行頭の書き方はアプリで正規表現で見分け、行の中だけを渡す（`Document.parseInline`、GitHub 拡張で取り消し線も読む）。

## 理由

- 表示を変えるだけなので、土台の形（ADR 0001）も衝突検知のプロンプトも変えずに済む。
- 1行を1まとまりにしておけば、行を押して編集する操作と、行ごとの出どころ・左余白の色線がそのまま使える。
- `flutter_markdown` は開発が止まっている。文書全体を描く部品なので、1行ずつ渡すと字下げした行をコードブロックとして扱い、文字のスタイルもトークンから外れる。

## 制約・既知の問題

- 差分化のプロンプト（`api/src/foundation/patchify.ts`）は「`## ` は見出し、`- ` は項目」のまま。変えると `eval/` を回す必要があるので分けた。`###` などを使ったノートでは、Gemini が見出しを書き換えや衝突の相手に選び、検証で受け付けられないことがある。
- リンクは押しても開かない。行を押すと編集が開くので、押し分けられない。
- 斜体は、同梱の書体（BIZ UDPGothic）に斜体が無いため、表示する環境によっては傾かない。
- 表・コードブロック・チェックボックス（`- [ ]`）は記号のまま出る。
