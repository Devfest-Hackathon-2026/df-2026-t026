# 0003 デモ版の API は合言葉で守る

- 日付：2026-11-08
- 状態：採用

## 背景

- 仕様ではデモ版は「認証なし（単一ユーザー固定）」だった。
- API は Web 版（Firebase Hosting）からブラウザで直接呼ぶので、Cloud Run は誰でも呼べる設定にしている。API の URL は Web 版の JS に入るので隠せない。
- このままだと、URL を知った人が Gemini を呼んでこちらに課金させたり、デモのデータを書き換えたりできる。

## 決定

- API は `X-Passcode` ヘッダーで合言葉を受け、環境変数 `PASSCODE` と一致しなければ 401 を返す（`/health` は除く）。`PASSCODE` を決めていないとき（ローカル開発）は確かめない。
- 合言葉は Terraform の変数（`infra/terraform.tfvars`、git の管理外）から Cloud Run の環境変数に渡す。HTTP ヘッダーで送るので、英数字・ハイフン・下線だけにする。
- アプリは 401 を受けたら合言葉を聞き、合っていればブラウザ（shared_preferences）に覚えておく。
- ローカルで API を動かすときは、既定で自分のマシン（127.0.0.1）からだけ受ける。Cloud Run では Dockerfile で `HOST=0.0.0.0` にする。
- 使いすぎに気づけるよう、プロジェクトに予算アラート（メール）を付ける。

## 採らなかった案

- Google ログイン（Firebase Authentication）：一人ずつのデータに分けられるが、変更が大きく、Google ログイン用の OAuth クライアントは Terraform で作れない。審査員に触ってもらうにも許可リストへの追加が要る。本番に向けて認証を入れるときに改めて決める。ユーザー ID は `api/src/app.ts` のミドルウェアで差し込める形のままにしてある。
- 公開を審査の直前まで遅らせる：その間デプロイの流れを確かめられない。

## 割り切っていること

- 合言葉は全員で共有し、データも全員で共有する（単一ユーザー固定のまま）。
- 合言葉は Cloud Run の設定画面でプロジェクトのメンバーから見える。Secret Manager は使わない。
- 回数制限はしていない。総当たりされにくいよう、合言葉は十分長くする。
