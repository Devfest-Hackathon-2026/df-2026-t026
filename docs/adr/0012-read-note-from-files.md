# 0012 ノートを作るときに、PDF・画像から本文を読み取る

- 日付：2026-11-09
- 状態：採用

## 背景

- 職場のマニュアルは、紙を撮った写真や PDF でしか手元に無いことが多い。「ノートを作る」画面は本文を貼り付けるか白紙から始めるかだけで、文字を打ち直す必要があった。
- 入力ページでは PDF・画像を添えて Gemini で書き起こしているが（ADR 0005）、それは「言われたこと」を起こすプロンプトで、ノートの本文を起こすものではない。

## 決定

1. 「ノートを作る」画面の本文の欄の下に「ファイルから読み取る」を置く。添え方は入力ページとそろえ、「ファイルを選ぶ」・スマホの「写真を撮る」・PC の貼り付けとドロップで選べる。形式は PDF・PNG・JPEG・WebP・HEIC、合わせて 10MB まで。
2. 選んだらすぐ Gemini を1回呼び（`POST /read`、`api/src/format.ts`）、書いてある通りの文と、ノートの題名の案を返させる。整形は頼まない。整えたいときは「マークダウンに整える」（ADR 0011）を押す。
3. 読み取った文で本文を置き換える。題名が空のときだけ、題名の案を入れる。作るまでは手で直せる。
4. ADR 0011 と同じく、ノートの状態には触れない別の呼び出しとし、ADR 0002・0006 の呼び出しの数には数えない。

## 理由

- 読み取りと整形を分けると、整形のやり方を1か所（ADR 0011）にまとめておける。読み取った文を確かめてから整えるかを選べる。
- 題名は1回の呼び出しに一緒に返させるので、呼び出しは増えない。

## 制約・既知の問題

- 本文は置き換えるので、書いていた本文は消える。何枚かに分かれた資料は、一度にまとめて選ぶ。
- 画面のどこにドロップしても読み取る（入力ページと同じく、ページ全体で受ける）。下の入力ページには渡さない。
