# 0011 ノートを作るときに、本文を Gemini でマークダウンに整える

- 日付：2026-11-09
- 状態：採用

## 背景

- ノートは1行を1まとまりとするマークダウンで描き（ADR 0009）、差分も行で当てる（ADR 0001）。
- 職場のマニュアルや自分用のメモを貼ると、見出しも箇条書きも無い平文のことが多い。1行に決まりが何個も詰まっていると、行を押して直す・食い違いを行で示す、がやりにくい。

## 決定

1. 「ノートを作る」画面に「マークダウンに整える」を置く。押したときだけ Gemini を1回呼ぶ（`POST /format`、`api/src/format.ts`）。打つたびに候補を出す形（コード補完のようなゴースト表示）は、呼び出し回数と費用が増え、スマホに Tab キーも無いので採らない。
2. 返ってきた案は保存せず、ノートと同じ見た目でそのままモーダルに見せる。前は今の本文との違い（増えた行・消えた行）を欄の下に見せていたが、git などの差分に慣れていない人には読みにくいのでやめた（2026-11-09）。今の本文も「ノートの形で見る」で同じ見た目のモーダルに出せる。「この形にする」で本文を置き換え、作るまでは手で直せる。整えた内容を確かめるのは利用者で、バックエンドは JSON スキーマの検証だけをする。
3. 言葉・数値・順番は変えさせない。見出しは `## `、項目は `- `、順に意味のある手順は `1. ` に寄せる。差分化のプロンプトが `## ` と `- ` を前提にしているため（ADR 0009 の制約）。
4. ノートの状態には触れない。土台（差分）にも衝突検知にも入らない別の呼び出しとし、ADR 0002・0006 の呼び出しの数には数えない。

## 理由

- 押したときだけ呼ぶので、呼び出しは利用者が頼んだ回数で済む。
- 案を見せてから受け入れる形は、コードの AI アシスト（提案を見てから適用する）と同じで、勝手に本文が書き換わらない。

## 考える量（2026-11-10 追記）

整形は考える量を LOW にする。言葉を並べ替えるだけの作業で、既定のままだと考えた分（約900〜1,200トークン）が出力（約80トークン）の十数倍あり、時間と費用の大半を占めていた。

平文8件（詰まった平文、「・」と【】の箇条書き、①②の手順、マークダウンまじり、誤字、全角の数字、入れ子になる分量、介護の申し送り）を、既定と LOW で交互に2回ずつ回して比べた（`gemini-3.8-flash`）。言葉が変わっていないかは、マークダウンの印・箇条書きの記号・空白・句読点を除いて、元の文と同じ文字が同じ順に並ぶかで見た。

| | 既定 | LOW |
|---|---|---|
| 1件の時間（中央値） | 12.7 秒・15.6 秒 | 6.3 秒・5.2 秒 |
| 考えた分（1件あたりの平均） | 920・1,207 トークン | 162・156 トークン |
| 費用の見積もり（1件あたり） | 約0.60円・約0.77円 | 約0.18円・約0.17円 |
| 送った本数（8件で） | 11本・10本 | 9本・9本 |
| 言葉が変わったケース | 0件・0件 | 1件・1件 |
| ノートの書き方を守らなかったケース | 0件・0件 | 0件・0件 |

- LOW で言葉が変わったのは2回とも同じ1件で、「…の材料 じゃがいも3個、…。作り方は、肉を炒めてから…」の「作り方は、」を見出し「## 作り方」にして「は」を落とした。既定は2回とも「## 作り方は、」のまま見出しにし、材料の各行にも「、」「。」を残した。意味は変わらず、LOW のほうがノートとして読みやすいので、LOW にする（案は利用者が見てから受け入れる）。
- 誤字（「冷蔵こ」「終らせる」）と全角の数字は、どちらも直さずに残した。
- 費用は単価（入力 $0.75・出力 $3.75 / 100万トークン、外部のまとめサイトの値）と1ドル150円で見積もった。

## 制約・既知の問題

- 本文全体を一度に送って返させるので、長い本文では待ち時間が延びる。1回の上限時間は `gemini.ts` の `httpOptions` のまま。
- 言葉を変えていないかはバックエンドでは確かめない。利用者が案を見て決める。
- ノートを作った後の直接編集には付けていない。
