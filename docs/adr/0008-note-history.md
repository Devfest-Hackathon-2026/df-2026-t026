# 0008 ノートの履歴を、版の幹と食い違いの枝のグラフで見せる

- 日付：2026-11-08
- 状態：採用

## 背景

- ノートは「元の本文＋反映済みのパッチ」として持っている（ADR 0001）が、いつ・誰の言葉で・どう変わったかを順に追える画面がなかった。
- 利用者から、ノートの履歴を git のコミットやブランチのように見たい、版ごとの差分も見たいという要望があった。

## 決定

1. **履歴はアプリで組み立てる。API と保存の形は変えない**
   - `GET /manuals/:id` が返す元の本文・パッチ（反映日時つき）・記録・確認から、反映した順にパッチを当て直し、各版のノートを作る。当て方はバックエンドの `applyPatch` と同じにする。
   - 版管理（Firestore で自前管理か Git か）は決めない。ADR 0001 の「パッチ1件をコミット1件に写せる」をそのまま使う。（2026-11-10 追記：ADR 0023 で Firestore で自前で持つと決めた）
2. **幹と枝**
   - 幹は、ノートを作った版と、反映したパッチ。同じ記録から続けて反映したパッチ（確定で2行を1行にまとめたときなど）は1つの版にする。
   - 「ノートのまま」と確定した記録はパッチを作らないが、後で見せる証拠なので、幹に版として残す。
   - 枝は、ノートと食い違った記録（`contradiction`）だけにし、1本の枝を1つの食い違いにする。記録した時点の版から分かれ、確定した版に合流する。まだ確認していない枝は今まで伸ばし、グラフの横幅が同時に抱えている未確認の数を表すようにする。
   - 同じ内容・未反映・反映しないは、ノートから分かれた状態を持たないので枝にせず、記録したときの版に付ける。
3. **見せ方**
   - ノート画面から開く。広い画面では上部バーのすぐ下のノートのタブの「履歴」、狭い画面では下のタブバーの「履歴」から移る（前は広い画面では上部バーの右の「履歴」。共有と同じ枠のボタンで目立たなかったので、2026-11-10 にタブにした）。新しい順に並べ、広い画面では左にグラフ、右に選んだ版の差分を、狭い画面では押して差分の画面へ進む。
   - 幹と枝の形が一目で見えるよう、1件を同じ高さの1行に詰める。線と点は Miro のコネクタと図形の枠のように明るい色で軽く見せ、幹は反映済みの緑、あとで確認の枝は黄、確認済みの枝は灰色にする。まだ確認していない枝は、記録した所から今まで点線で伸ばす。縦は時間の軸なので、幹もいちばん新しい版から今まで伸ばし、未確認の枝と並べる。
   - 版の行は「誰が・いつ → 何をしたか → 増減」、ノートを変えずに確定した版は「変更なし」とし、版に付けた記録は「同じ内容 1」のような小さな印で示す。枝の行は、何と何が食い違ったか（ノートの行 ／ 言われた行）を先に、誰がいつ言ったかを後ろに添える。収まらなければ末尾を省き、全文は差分の側で見せる。
   - 版の差分は、その版のノート全文に、前の版から増えた行・消えた行の印を付けて見せ、その版に付けた記録を並べる。枝は、ノートに入れていない差分だけを見せる。
   - 画面では git の言葉（コミット・ブランチ・マージ）を使わず、「版」「確認」で書く。
   - 見るだけにし、前の版には戻さない（spec の「やらないこと」）。

## 理由

- 食い違いは「ノートから分かれた言い分が、確認して合流する」形で、git のブランチとマージにそのまま重なる。板挟みになったことと、誰に確認して決まったかを一目で追える。
- 保存の形を変えないので、版管理をどちらに決めても画面はそのまま使える。

## 制約・既知の問題

- パッチの当て方を、バックエンド（`api/src/foundation/manual.ts`）とアプリ（`app/lib/history.dart`）の2か所に持つ。当て方を変えるときは両方を合わせる。
- 表示のたびに全パッチを当て直す（ADR 0001 と同じ）。
- 直接書いた行の食い違いは、行がもう幹に入っているので枝にしない。
