# 0020 共有した相手が答えた・直したことを、持ち主に通知で知らせる

- 日付：2026-11-10
- 状態：採用

## 背景

- 共有した相手（教える人）が確認に答える（ADR 0017）と、持ち主の側では「あとで確認」が「いまはありません」になり、記録した発言に付箋が1枚増えるだけだった。答えが届いたことに、持ち主が気づけない。
- 共有した相手がノートの行を直しても（ADR 0016）、持ち主の側では本文の行が変わるだけで、記録した発言には何も出なかった。

## 決定

1. **通知は、自分のノートでほかの人がしたことから作る**
   - 対象は、自分が持ち主のノートだけ（共有されたノートでの出来事は知らせない）。
   - 種類は2つ。ほかの人が確認に答えた（`resolution.answeredBy` があり、記録を見せて済ませた確定ではないもの）と、ほかの人が行を直した（`fromEdit` で `editedBy` のある記録）。
   - 出来事を別に保存せず、ノートの記録・パッチ・確認から毎回組み立てる（`GET /notices`）。土台の形は変えない。新しい順に50件まで返す。
2. **どこまで見たかはサーバーで覚える**
   - 人ごとに「通知を最後に見た時刻」を `users/{id}/notices/seen` に置く。それより後の通知を「新しい」とする。PC とスマホで同じになる（ADR 0015 と同じ考え）。
   - 通知のページを開くと、その時刻を今にする（`POST /notices/seen`）。1件ずつの既読は持たない。
3. **自分を押すと通知が見られる**
   - サイドバー（スマホはメニュー）のいちばん下の自分を押すと「通知」のページを開く。新しい通知があれば、自分の右に件数を出す。
   - 通知のページには「〇〇が回答しました」「〇〇がノートを編集しました」と、ノートの題名・何が変わったかを新しい順に並べ、押すとそのノートを開く。
   - 名前とアイコンのページへは、通知のページの「名前とアイコンを変える」から移る（前は自分を押すと直接移った）。
4. **ほかの人が直した行は、記録した発言にも細く出す**
   - ノートのページの記録した発言に、共有した相手が行を直した記録を、付箋より細い白い札で時刻の順に混ぜて出す。押すと履歴を開き、その版を選ぶ。
   - 持ち主が自分で直した行は、今までどおり出さない（本人の文なので）。

## 理由

- 出来事を別に保存すると、確定・編集のたびに書く所が増え、記録と食い違うおそれがある。答えも直しも、もう記録とパッチに「だれがいつ」付きで残っている（ADR 0013・0017・0018）ので、そこから組み立てれば足りる。
- 1件ずつの既読は、通知が少ないうちは要らない。「ページを開いたら見た」で、新しい物が来たことは分かる。

## 採らなかった案

- 端末だけで既読を覚える：API はほぼ変えずに済むが、別の端末では同じ通知がまた新しく出る。
- サイドバーのノートごとに「新しい変更」の印を付ける：利用者が、自分を押して通知の欄で見る形を選んだ。
- 共有された人にも通知する：利用者が持ち主だけを選んだ。

## 割り切っていること

- 通知を見るまで、ほかの画面は自分では新しくならない。サイドバーの件数は、何か操作してデータを読み直したときに増える（ADR 0016 と同じく配信の仕組みは作らない）。（2026-11-10 追記：通知は `GET /home` でノートと一緒に読み、アプリの store に持つようにした。件数が増えるのは、アプリを開いたとき・アプリに戻ってきたときで、自分が何か書いても読み直さない。ADR 0021）
- ほかの人が言われたことを記録した（入力ページから記録した）ことは、通知に出さない。
- 共有した相手を外しても、その人が前にした答え・直しの通知は残る。
- スマホでは、三本線のメニューを開くまで件数は見えない。
- 最初は「見た時刻」が無いので、それまでのほかの人の答え・直しはすべて新しいとして出る。
