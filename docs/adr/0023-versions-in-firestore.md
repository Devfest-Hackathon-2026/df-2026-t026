# 0023 ノートの版は Firestore で自前で持ち、裏で Git は使わない

- 日付：2026-11-10
- 状態：採用（spec の「未定事項：文書の版管理」と、ADR 0001 の「版管理はまだ決めていない」を閉じる）

## 背景

- spec と ADR 0001 は、文書の版管理を「Firestore で自前管理」か「裏で本物の Git」かで未定にし、決まるまでどちらかに依存する実装をしないとしていた。
- その間に、土台（元の本文＋反映済みのパッチ。ADR 0001）を Firestore に置いたまま、履歴のグラフ（ADR 0008）、共有と共同編集（ADR 0013・0016）、記録した人（ADR 0018）、通知（ADR 0020）、資料（ADR 0019）を作った。どれもパッチと記録を Firestore のドキュメントとして読む前提で、Git を前提にしたものは無い。
- 未定のままだと、spec・AGENTS.md・ADR 0001 の記述が実装と合わない。

## 決定

1. 版は、今の形のまま Firestore で持つ。`users/{持ち主}/manuals/{ノート}` の元の本文と、その下の `patches`（反映した時刻つき）が正で、ある時点の版は、その時刻までのパッチを当て直して作る（ADR 0001・0008）。
2. 裏で Git のリポジトリは持たない。diff・blame・ブランチに当たるものは、行ごとのパッチ ID（blame）、版ごとの増えた行・消えた行（diff）、食い違いの枝（branch と merge）として、アプリとバックエンドで組み立てる（ADR 0001・0008）。
3. 保存先は今までどおり `Store` インターフェースの裏に置く（`MemoryStore`・`FirestoreStore`）。

## 理由

- 作ったものがすべて Firestore の形に乗っていて、Git に移すと、共有・認可（`load`）・消す・通知・資料の読み書きを全部作り直すことになる。
- Cloud Run のファイルは、インスタンスが入れ替わると消えるメモリ上の場所で、Git のリポジトリを置き続けられない。置くなら Cloud Storage などに出し入れする仕組みと、同時に書いたときの排他が要る。
- このアプリの単位は行と発言で、版の比べ方もグラフも、パッチ1件をコミット1件として読めば足りている（ADR 0008）。

## 採らなかった案

- **裏で本物の Git（ノートごとにリポジトリ）**：diff・blame・merge をそのまま使えるが、上の理由で、置き場所・排他・共有の認可が増える。
- **未定のまま残す**：実装はもう Firestore の形に寄っているので、未定と書き続けても選べる道は増えない。

## 割り切っていること

- 表示のたびに全パッチを当て直す（ADR 0001）。パッチが数千件になったら、版のスナップショットを持つことを考える。
- パッチの当て方を、バックエンド（`api/src/foundation/manual.ts`）とアプリ（`app/lib/history.dart`）の2か所に持つ（ADR 0008）。
- 書き込みの重なりをトランザクションでは防いでいない（ADR 0001 の既知の問題）。
