# 0009 配った ID とパスワードでログインする

- 日付：2026-11-09
- 状態：採用（ADR 0003 の合言葉を置き換える）

## 背景

- これまでは合言葉（ADR 0003）を全員で共有し、データも全員で1人分（`demo`）を共有していた。
- 使ってもらう人ごとにノートを分け、知らない人に使わせないために、ログインが必要になった。
- 使う人はこちらで決めて配るので、自分で登録してもらう必要はない。

## 決定

- アカウントはこちらで作って ID とパスワードを本人に渡す。登録の画面や API は作らない。作るときは `api/scripts/create-account.ts`（`pnpm create-account <ID>`）で Firestore に直接書く。パスワードを省くと作って表示する。同じ ID で回すとパスワードを置き換える。
- ログイン ID をそのまま `userId` にし、データは `users/{ログイン ID}/manuals/...` に分かれる。これまでのデータ（`users/demo`）は、ID `demo` のアカウントを作ると引き継げる。
- アカウントは `accounts/{ログイン ID}` に、パスワードを scrypt（`node:crypto`）でハッシュにして持つ。
- `POST /login` で ID とパスワードが合えばトークンを返し、`sessions/{トークンの SHA-256}` に誰のトークンかを持つ。以後は `Authorization: Bearer <トークン>` で受け、トークンから `userId` を決める（`/health`・`/login` は除く）。ブラウザの WebSocket はヘッダーを付けられないので、音声入力（`/dictation`）だけはクエリ `token` でも受ける。
- アプリは 401 を受けたら ID とパスワードを聞き、受け取ったトークンをブラウザ（shared_preferences）に覚えておく。
- ローカル開発（メモリに保存）では、起動時に ID `demo` と、本番に配ったのと同じ ID のアカウントを作る。パスワードはどれもローカル専用の `demo` にし、本番のパスワードはリポジトリに入れない。確かめない設定は残さない。
- 合言葉（`PASSCODE`・`X-Passcode`）はやめる。

## 理由

- 毎回 ID とパスワードを送る形にすると、リクエストのたびに遅いハッシュ（scrypt）を計算することになる。入力ページは開くたびにノートの数だけ並べて呼ぶので待ちが増える。
- トークンを署名付き（JWT など）にすると、署名の鍵を Terraform で配る必要があり、1人だけ止めることもできない。Firestore に持てば鍵が要らず、ドキュメントを消せば止められる。1回の呼び出しで Firestore を1回多く読むが、ノートを読むのに比べれば小さい。
- メンバーは Firestore を読める（`roles/datastore.viewer`）ので、パスワードもトークンもそのままは置かず、ハッシュにして持つ。

## 採らなかった案

- Google ログイン（Firebase Authentication）：ADR 0003 と同じ理由（OAuth クライアントを Terraform で作れない、配る相手を許可リストに足す手間）で見送る。
- 合言葉を残し、その上にログインを重ねる：守りが二重になるだけで、配るものが増える。

## 割り切っていること

- トークンに期限を付けない。止めるときは `sessions` のドキュメントを消す（パスワードを置き換えても、ログイン済みのトークンは使えたまま）。
- ~~ログアウトの操作は作らない。~~ → 作った（下の「ログアウト」）。
- ログインの回数制限はしない。パスワードは省いて作らせ、十分長くする。
- 音声入力のトークンは URL に入るので、Cloud Run のリクエストのログに残る（合言葉と同じ）。

## ログアウト（2026-11-10 追記）

- 端末を人に渡す・別の ID で入り直すときのために、「名前とアイコン」のページに「ログアウトする」を置く。
- `POST /logout` で、使っているトークンの `sessions` のドキュメントだけを消す。ほかの端末でのログインはそのまま。受けたインスタンスが覚えたセッションも消すが、ほかの Cloud Run のインスタンスが覚えた分は最長5分そのトークンを通す（呼び出しのたびに Firestore を読まないための割り切り）。
- アプリはブラウザに覚えたトークンも消し、画面を全部閉じて入力ページを開き直す（トークンが無いのでログインの欄が出る）。待ち受けや書きかけを前の人のまま残さないため。
- サーバーでもうトークンが止まっていた（401）ときもログアウトしたことにする。つながらないときはエラーを出してログインしたままにする（サーバーでトークンが生きたまま、止めたように見せない）。
