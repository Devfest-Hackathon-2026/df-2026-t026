# 0017 共有された教える人は、確認に自分で答えて確定し、確認の聞き方は見せない

- 日付：2026-11-10
- 状態：採用（ADR 0016 の「共有された人も確定できる」のうち、確定の仕方を置き換える）

## 背景

- ADR 0016 で、共有された人も確認リストから確定できるようにした。ただし、確定の記録は「確認した相手」を手で入れる形のままで、新人が聞いて書いたのか、教える人が自分で決めたのかを区別できなかった。確認印（はんこ）は、だれが押しても「〇〇 に確認」になり、教える人が決めた記録にならない。
- 確認のページの「誰に確認する？」（確認先の候補・その理由・聞き方の例）は、新人がだれにどう聞くかを決めるためのもの。ノートを共有された教える人は、聞かれる側なので、自分への聞き方の例を見せる意味がない。

## 決定

1. **共有された人（持ち主以外）は、自分の答えとして確定する**
   - 確認のページでは「聞いた結果を記録する」の代わりに、すぐ答える欄を出す。どちらにするか（ノートのまま・言われた通り・別の内容）とメモを選び、「答えて確定する」を押す。確認した相手の欄と日付は無い。
   - API（`POST /manuals/:id/checks/:cid/resolve`）は、持ち主でない人が呼んだら、送られた `decidedBy` を使わず、その人の名前（ADR 0010）を決めた人にし、`resolution.answeredBy` にその人のログイン ID を入れる。持ち主は今までどおり `decidedBy` を送り、`answeredBy` は付かない。
   - 決めた答えは、今までどおり「誰がいつ言ったか」付きの発言として土台に残す（ADR 0001）。発言者はその人の名前。
2. **本人が決めた記録は「が決定」と見せる**
   - `answeredBy` のある確定は、ノートの行・確認リスト・履歴・書き込む前の確認では「〇〇 11/10 が決定」、確認印は上の文字を「決定」にする。新人が聞いて書いた確定は今までどおり「〇〇 に確認」。
3. **共有された人には「誰に確認する？」を見せない**
   - 確認のページで、確認先の候補・その理由・聞き方の例は持ち主にだけ出す。共有された人には、食い違い（ノート ／ 言われた行）と AI の理由、答える欄だけを出す。
   - 隠すのは画面だけにする。API は今までどおり確認の項目を丸ごと返す。教える人は裏をかく相手ではなく、聞き方を見せないのは画面を分かりやすくするためなので、応答を人ごとに作り分けない。

## 理由

- 決めた人をログインから取れば、はんこが「教える人が決めた」証拠になる。手で入れる名前は新人の聞き取りなので、区別して残す価値がある。
- 衝突検知に渡す文脈（`manualContext`）とプロンプトは変えない。`answeredBy` は画面の出し分けにだけ使い、AI にはこれまでどおり「〇〇に確認」と渡す。

## 採らなかった案

- 押した人の ID を記録に足すだけで、画面は変えない：記録には残るが、はんこを見ても教える人が決めたのか分からないまま。
- 聞き方の例だけを隠し、候補と理由は見せる：候補は「だれに聞くか」なので、聞かれる側にはやはり要らない。
- API の応答から聞き方を外す：応答を人ごとに作り分けることになり、書き込みのたびに読み込んだ確認の項目を書き戻す所（確定）で、外した中身を消してしまうおそれがある。

## 割り切っていること

- 共有された人は、ほかの人から聞いた結果を記録することはできない（自分の答えとしてだけ確定する）。教える人ではない同僚に共有したときも同じ。
- 共有された人の答えは、記録した日（日本時間の今日）に決めたものとして残る。日付は選べない。
- 衝突検知に渡す文脈では、本人の決定も「〇〇に確認」と書く（プロンプトの評価を測り直さないため）。
