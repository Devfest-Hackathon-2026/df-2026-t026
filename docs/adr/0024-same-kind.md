# 0024 分類に same（同じ内容）を足して4つにし、update は入れない

- 日付：2026-11-10（決めたのは 2026-11-08 の #10・#20。ADR は後から書いた）
- 状態：採用

## 背景

- 衝突検知の分類は `addition`・`qualification`・`contradiction` の3つで、言い方が違うだけで同じ内容の発言も `addition` だった。書き込むと、同じ内容の行が本文に重なった。
- #10 で、検証用のモックが使っていた5つ（矛盾・条件違い・更新・補足・同じ）に分ける案が出た。`update`（「〜から変わった」）を分けると聞き方を変えられる一方、モックの評価では本来は矛盾のケースを `update` と判定したものがあった。

## 決定

1. 分類は `same` / `addition` / `qualification` / `contradiction` の4つにする。名前はコード・UI・評価でそろえる（AGENTS.md）。
2. `same` は、ノートか資料のどこかの行と、言い方が違うだけで同じ内容のとき。新しい情報が少しでもあれば `same` にしない（`api/src/conflict/check.ts` の `checkRules`）。同じ内容の行は `sameLine`（資料の行なら `materialRef`）で指し、スキーマで項目の行を指しているかを確かめる。
3. `same` は本文を変えない。書き込む前の確認では「書き込まない」を主にし、判定が外れたとき用に「それでも書き込む」を残す。入力ページからの記録で自動で書き込むときも、`same` は書き込まない（ADR 0006 の追記）。
4. 同じことを言った人は、その行の出どころに「佐藤さん（2026-11-09）も同じ」と添えて、次の判定に渡し、画面ではその行の横に出す。同じことを複数の人が言った裏付けになる。
5. `update` は入れない。「変わった」と言われても、ノートと両立しなければ `contradiction` として聞きに行く。
6. 評価では、1つの発言から複数のパッチが出たら、いちばん重い分類（`same` < `addition` < `qualification` < `contradiction`）をその発言の判定にする（`eval/README.md`）。

## 理由

- `same` を誤って判定しても、外れた先は追記か矛盾なので、矛盾の取りこぼしは増えない。`update` は、外れると矛盾を聞きに行かない側に倒れ、プロダクトの芯（板挟みから身を守る）に直結する取りこぼしになる。
- 本文に同じ行が重ならない。複数の人が同じことを言った記録は、spec の体験の流れ 7（証拠として使う）を強める。
- 分類名を増やさないので、指標（矛盾の取りこぼし率・誤って聞きに来た率）の数え方は変わらない。

## 採らなかった案

- **5つに分ける（#10 の案 A）**：上の取りこぼしの危険と、新人に5つは多いため。
- **3つのまま、理由の種類（`same`・`update` など）を足す（案 B）**：分類名は変えずに済むが、本文に書き込むかどうかを分類で決めている作りと合わない。

## 割り切っていること

- 「〜から変わった」と言われたときの聞き方も「どちらに合わせればよいですか」になる。
- モックの評価セットの `update` 6件は、読み替えが分かれるので `eval/cases.json` に入れていない。
