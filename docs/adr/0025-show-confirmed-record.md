# 0025 確定済みの記録と食い違ったら、記録を見せて決着できるようにする

- 日付：2026-11-10（#100・#116・#121・#124・#129 で決めたことを、後から ADR にまとめた）
- 状態：採用

## 背景

- 前に確認して確定した内容と、別の人の言ったことが食い違ったとき、確認のページは「誰に確認する？」と「聞いた結果を記録する」へ誘導するだけで、もう一度聞く流れしかなかった。確定の記録は同じ画面に出ず、「どちらに決まった？」は言われた側が先に選ばれていて、そのまま押すと前の決定が覆った。
- このアプリの差別化は「確定の記録が教わる人を守る」こと（spec の体験の流れ 7）で、デモの山場もこの場面だが、画面ではそこがいちばん弱かった（審査員役のエージェントの指摘）。

## 決定

1. **対象**：確認待ちの食い違いの相手が確定済みの記録のとき。相手の行に確定の印があるとき、補足で書き換わった行の確定をさかのぼれるとき（#96）、相手の行が書き換えられてもう無く前の確定と同じ内容のとき（#86・#95）、資料の行に結び付いた確定のとき（ADR 0019）。ほかの確認は変えない。
2. **記録を見せる**：記録した直後の結果のカードと確認のページに、前の確定の記録を確認印つきで出し、相手に見せる文（例：「11/7 に店長に確認して、「塩 小さじ1/2」に決まっています（1/2で統一）。」）をコピーできるようにする。文は AI ではなく確定の記録から組み立てる。
3. **1回で決着する**：その下に主のボタン「記録を見せて、ノートのままにする」を置く。相手の行が書き換えられていたら「記録を見せて、書き換える前に戻す」、資料なら「記録を見せて、資料のままにする」、それ以外で決まった内容に戻すなら「記録を見せて、確定した内容にする」。押すと `POST /manuals/:id/checks/:cid/resolve` に `{ shownFrom: 前の確認の ID }` だけを送り、結果のカードはその場で「確認済み」に替わる。
4. **見せた記録として残す**：サーバーは決めた人・日付・内容・メモ（と `answeredBy`）を前の確定から写し、`resolution.shown`（見せた人と今日）を付ける。答えの発言は、見せた人の発言「11/7 店長に確認した記録（1/2で統一）を見せた」として残す。ノートの行は前の確定の内容のままにし、行を2つにしない。
5. **既定の選択を覆らない側にする**：確認のページの「どちらに決まった？」は、相手が確定済みの記録なら「ノートのまま」（行が無ければ「書き換える前の内容」）、資料なら「資料のまま」を最初に選んでおく。
6. **判定には重ねない**：見せて済ませた確定は、判定に渡す「確定済みの記録」に重ねて載せず、見せた人の発言も「これまでの発言者」に入れない。資料が0冊のときのプロンプトは、見せる前後で1文字も変わらない。
7. **共有された人が押しても「決定」にしない**：決めたのは前の人なので、ADR 0017 の本人の答えにはしない。通知（ADR 0020）にも出さない。
8. もう一度聞く流れ（誰に確認する？・聞いた結果を記録する）は、確認のページの「もう一度聞くなら」の区切りの下に残す。

## 理由

- 確定の記録を見せて済ませられれば、新人は同じことを何度も聞かずに済み、前の決定を根拠に自分を守れる。
- 見せる文を確定の記録から組み立てれば、AI が言い換えて中身がずれることが無い。
- 前の確定と同じ人・日付で確定し直すと、前に決めた人がその日に何も言っていないのに、その人の発言として残る。見せた人の行いとして残せば、記録が事実と合う。

## 採らなかった案

- **前の確定と同じ人・日付・内容で、ふつうの確定として送る**（#116 の最初の形）：前に決めた人の発言として残り、記録の文の日付も重なった（#118）。
- **確認のページにだけボタンを置く**：決着の一手が、結果のカード → 記録した結果 → 確認リストの右をスクロールした先、まで進まないと出なかった（#129）。
- **もう一度聞く流れだけにする**：確定の記録が教わる人を守る、という差別化が画面に出ない。
