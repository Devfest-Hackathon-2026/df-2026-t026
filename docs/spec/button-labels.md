# ボタンの名前

アプリ内のボタンの名前の一覧。使う人が「押すと何が起きるか」を言葉だけで分かるように、名前はここで決めてからコードに入れる。

- 名前を変えたいときは「新しい名前」に案を書き、メモに理由を書く。空欄は今の名前のまま
- 案の名前でコードを直したら、「今の名前」を書き換えて「新しい名前」を空にする。前の名前はメモに「前は「〜」」と残す
- ボタンを足す・名前を変えるときは、この一覧も同じ PR で更新する

## 名前の付け方

- 押した結果を動詞で言う。例：「差分を作る」ではなく「ノートと照らし合わせる」
- 「差分」「反映」「承認」「登録」など、git や業務システムの言葉を使わない
- 同じ操作は、どの画面でも同じ言葉にする。例：言われたことをノートの本文に入れるのは「書き込む」、入力をやめて元に戻すのは「やめる」
- 違う操作に同じ言葉を使わない。例：入力ページの「記録する」（言われたことを残す）と、確認のページの「記録する」（聞いた結果を残す）を分ける
- 画面の他の言葉に合わせる。画面では「言われたこと」「聞く」と言っているので、ボタンも「言われたことを直す」「〇〇 に聞いた」とする

種類の見方：

| 種類 | 見た目 | コード |
|---|---|---|
| 主 | 塗りつぶし。その画面でいちばん押してほしい操作 | `MoonFilledButton` |
| 枠 | 枠線だけ | `MoonOutlinedButton` |
| 文字 | 文字だけ。控えめな操作 | `MoonTextButton` |
| アイコン | 絵だけ。名前は読み上げ用（`semanticLabel`） | `MoonButton.icon` |
| 項目 | 一覧の1行 | `MoonMenuItem` |
| トグル | ON／OFF のスイッチ。名前は読み上げ用（`semanticLabel`） | `MoonSwitch` |
| タブ | 下のタブバーの1つ。アイコンと短い名前 | `MoonButton` |

## リワインドの待ち受け（`rewind_panel.dart`）

入力ページでリワインドを ON にしている間、書く欄の所に出る面。大きな丸いボタンは常に1つで、待ち受けの状態に合わせて名前が変わる。

| 今の名前 | 種類 | 出る場所・条件 | 押すと何が起きるか | 新しい名前 | メモ |
|---|---|---|---|---|---|
| いま言われたことをメモする | 主 | 大きな丸いボタン。待ち受けているとき | 押す前の発話を文字に起こし、未整理メモにためる | | 前は「直前の発話を残す」。「発話」は画面の他の場所で使っていない |
| 待ち受けを始める | 主 | 大きな丸いボタン。マイクを使えなかった・待ち受けが止まったとき | マイクを開き直して待ち受けを始める | | 前は枠のボタンを別に出していた。ボタンを1つにし、場所を変えない |

押せない間の名前：マイクの準備中は「マイクを準備しています…」、押した後は「話し終わるのを待っています…」。

| 言われたことを直す | 文字 | 言われたことの下。まだ書き込み・確定していないとき | 言われたことを直す欄を出す | | 前は「書き起こしを直す」。直すのは「書き込む内容」ではなく「言われたこと」だと分かるようにする |

| 直して照らし合わせ直す | 主 | 同上 | 直した文で AI の判定をやり直す | | 前は「直して差分を作り直す」 |

## 下のタブバー（`tab_bar.dart`）

サイドバーが出ない狭い画面で、ノート・確認リスト・履歴の画面の下に浮かせて出す。後ろが透けてぼける（UI ルールの例外。`--dart-define=TABBAR_BLUR=false` でぼかしを切れる）。押しても横から出てくる動きは付けない。キーボードが出ている間は隠す。

## 確認リスト（`check_list_screen.dart`）

ボタンは無い。「あとで確認」「確認済み」の各行を押すと、確認のページへ移る（広い画面では右に並べて出す）。「確認済み」の行には、誰がいつ確認したかを「〇〇 日付 に確認」の形で出す（前は小さい確認印）。
