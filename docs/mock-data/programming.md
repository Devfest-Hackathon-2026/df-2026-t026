## 審査員の動き（想定）

### 5分：山場だけ

1. `dev-newbie` でログイン。サイドバーに A〜C、「あとで確認」2 件、通知 2 件が見える
2. ① を送る → 「ノート：PR の説明に確かめ方を書く ／ 山本さん：書かなくていい」が並ぶ
3. 「確かめる」→ 確認先の候補と、そのまま Slack に貼れる聞き方の文面
4. 「聞いた結果を記録する」→ 中村さんに聞いた結果を記録 → 行に「中村さん 今日 に確認」
5. ⑥ を送る → 前の確定の記録が出て、「記録を見せて、ノートのままにする」の1回で決着（**先輩どうしの板挟みから身を守る場面**）
6. 「履歴」で、版の幹と食い違いの枝のグラフを見る

### 15分：ひととおり

7. ②③④ を続けて送り、追加・補足・同じ内容に分かれるのを見る
8. ⑤ で、1回の入力が障害対応メモと入社手続きのメモに振り分けられる
9. A の「資料」でコーディング規約を開く。⑦ を送り、「資料で前後を見る」で資料のその行へ。⑧ で、資料と食い違って確定した記録を見せて決着する
10. 「リワインド」を ON。未整理メモの「デバッグ中なら…」を送る → 発言者を補う → 資料と食い違う
11. ノートの行を押して直接書き換える（食い違う内容なら確認リストに入る）
12. 通知を開く →「中村さんが確認に答えました」「中村さんが行を直しました」
13. ログアウトして `dev-lead` でログイン → 共有された C の振り返りの件に「答えて確定する」
14. `dev-newbie` に戻る → 通知が1件増えている
15. 「ノートを探す」で「PR」と打つ。「＋」から、社内 wiki の文を貼り付けて「マークダウンに整える」でノートを作る
